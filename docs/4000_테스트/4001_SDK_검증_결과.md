# SDK 검증 결과

## 문서 정보

- 상태: 초안. 배포물 불일치 1건이 있으며 전체 통과 상태가 아니다. 2026-10-28 에뮬레이터의 제한된 읽기 호출을 추가 확인했다.
- 적용 범위: 문서에 수록한 SDK 5종의 공개 진입점·도메인 메서드와 보조 타입. SDK 버전은 API 연동 참조와 동일하다.
- 근거: 2026-10-27 사용자 전체 검증 요청, 공식 배포 AAR·소스 JAR, 로컬 JDK 17 및 Android SDK 환경.
- 관련 요구사항: REQ-CONTEST-001, REQ-CONTEST-009.

## 목적과 범위

기존 추출 목록의 자기 일치 검사와 배포물·실행 결과를 구분한다. 공개 API 이름·오버로드·타입 접근성을 배포 바이너리와 대조하고, Android 서비스 없이 실행 가능한 실제 SDK 모델의 경계·기본값·선택·동등성 계약을 실행한다.

차량 제어, 마이크·오디오 재생, 내비 앱, 위치 서비스, 서버 인증은 실제 Pleos 환경에서만 검증할 수 있다. SDK 서비스 동작을 가짜 결과로 대체하지 않았다. 모델 단위 검증의 통과를 전체 SDK 정상 동작으로 해석하지 않는다.

## 환경과 사전 조건

- JDK 17의 javac/java/javap를 사용했다.
- Vehicle 2.3.2, NaviHelper 3.0.5, FusedLocation 1.1.3, navi-data 3.0.4의 공식 AAR에서 classes.jar를 읽었다. 음성 SDK는 기존에 확보한 3.3.1 AAR 내부 클래스를 사용했다.
- 모델 실행에는 Kotlin stdlib 2.2.0, kotlinx serialization core/json JVM 1.6.3을 사용했다. 이 조합은 이번 JVM 모델 실행의 조건이며 Android 앱의 의존성 권장 버전이 아니다.
- `adb devices -l` 결과 연결된 기기가 없었다. 설치된 AVD는 Pixel_7이며 `google_apis_playstore` 이미지다. 확인한 로컬 Android SDK에는 Pleos AVD가 없어 실제 서비스 검증을 진행하지 못했다.
- 계정 승인·권한·실차 capability와 서버 자격 증명은 확인되지 않았다. 개인 비밀값을 검색하거나 기록하지 않았다.

### 기획 조사 중 실행 환경 재확인

2026-10-28 `adb devices -l`을 다시 실행한 결과 `emulator-5554`가 `device` 상태이며 `product:crp_avd`, `model:Connect_on_x86_64_emulator`, `device:crp_avd_x86_64`로 연결돼 있었다. 위의 연결 기기 없음은 2026-10-27 검증 당시 결과이며 현재 환경을 뜻하지 않는다.

같은 기기에 `adb -s emulator-5554 shell pm list packages pleos`를 실행하여 `ai.pleos.playground.service.vehicle`, `ai.pleos.playground.service.navi`, `ai.pleos.playground.service.location.fused` 등의 설치를 확인했다. 이 패키지 점검만으로는 서비스 연결·앱별 권한·capability·SDK 호출·실차 지원을 확인할 수 없다. 이후 실제 읽기 호출을 별도로 수행한 결과는 아래 최소 실험 절에 구분한다.

이어 읽기용 도움말 조회인 `adb -s emulator-5554 shell cmd car_service help`는 종료 코드 1과 `SecurityException: The command 'help' requires non-user build`로 거부됐다. 이 이미지에서는 해당 shell 도움말 경로를 사용할 수 없음을 확인했다. 이를 일반 앱의 SDK 접근 거부로 해석하지 않으며, root 전환이나 시스템 보안 설정 변경은 시도하지 않았다. 실제 차량 데이터 검증에는 공식 SDK를 사용하는 앱의 권한·연결·호출 결과가 별도로 필요하다.

## 에뮬레이터 읽기 호출 최소 실험

2026-10-28 기획 후보의 필수 신호 확보 가능성을 확인하기 위해 [별도 진단 앱](../../tools/vehicle-runtime-probe/src/main/java/dev/onboard/probe/ProbeActivity.kt)을 만들고 실행했다. 기존 Onboard 앱을 변경하지 않았으며 제어 API·제어 권한을 넣지 않았다. Context7 도구가 제공되지 않아 Vehicle 2.3.2 공식 배포 소스와 Android 공식 참조로 호출을 확인했다. 기본 SDK 모델 검증과 다른 실행이다.

- 빌드: Gradle 8.13, AGP 8.9.2, Kotlin 2.2.10, Microsoft JDK 21.0.12, JVM 대상 17, compileSdk 35, min/targetSdk 34.
- 기기: `emulator-5554`, product `crp_avd`, model `Connect_on_x86_64_emulator`.
- 앱: `dev.onboard.probe`, Vehicle 2.3.2. 설치 시 `-g` 옵션을 사용했으며, 앱에서도 읽기 권한 3종의 실제 grant 상태를 기록했다.
- 관측: `OnboardRuntimeProbe` 로그만 읽었다. 차량 상태를 바꾸지 않았고 20초 후 Activity 종료·해제를 수행하도록 구현했다.

공유 라이브러리 목록에는 `ai.pleos.playground.car`, `car-frameworks-service`가 있고 `android.car` 이름은 없었다. 그러나 선택 의존성 구성에서는 실제 `android.car.Car`와 `CarPropertyManager` 호출이 성공했다. 따라서 이름 목록만으로 표준 클래스가 없다고 판단해서는 안 된다. 특정 다른 라이브러리가 클래스를 공급한다고까지 확인한 것은 아니다.

조향각 공식 소스는 앞바퀴 각도·도 단위·왼쪽 음수라고 설명하지만, 위 capability 범위가 어떤 신호 스케일을 표현하는지는 미확인이다. 0 한 점과 범위만으로 문서 오류·핸들 회전각 신호라고 확정하지 않는다. 주차 궤적 계산에 사용하려면 비영점 값의 의미·부호·스케일과 실제 바퀴 각도, 휠베이스, 속도·기어의 시간 정렬을 먼저 확인해야 한다. 이 결과를 주차 복기 후보의 구현 완료로 해석하지 않는다.

추가로 [공식 Virtual Console 사용 가이드](https://document.pleos.ai/en/docs/pleos-only/app-test-guide/virtual-console-guide)는 Steering Angle 입력을 스티어링 휠 각도 -540~540도로 설명한다. [Android PERF_STEERING_ANGLE 정의](https://developer.android.com/reference/android/car/VehiclePropertyIds#PERF_STEERING_ANGLE)는 앞바퀴 bicycle-model 각도이며 운전대 회전각과 독립이라고 설명한다. 서로 다른 입력·출력 사이에 변환이 있을 수 있으므로 용어 차이 자체를 서비스 오류로 기록하지 않는다.

후속 시험안은 동일 기기에서 콘솔 입력 `0 → +10 → +100 → 0 → -10 → -100 → 0`에 대해 UI 설정값·시각과 SDK get·callback·수신 시각을 대조하는 것이다. 부호·배율·오프셋·누락·지연을 확인하되, 일대일 대응이 나와도 실차의 물리 각도 의미를 증명한 것으로 보지 않는다. 이 입력 시험은 아직 미실행이다. 전용 브라우저 연결이 없어 기존 Chrome 사용 여부를 사용자에게 확인 요청한 상태이며, 에뮬레이터 확장 제어 창은 열어 목록만 확인한 후 닫았다. 차량 상태 입력은 변경하지 않았다.

재현 명령은 저장소 루트에서 다음 순서다. `JAVA_HOME`·`ANDROID_HOME`은 실제 설치 경로로 설정하며 비밀값이 필요하지 않다.

```powershell
.\gradlew.bat -p tools/vehicle-runtime-probe assembleDebug --console=plain
adb -s emulator-5554 install -r -g tools/vehicle-runtime-probe/build/outputs/apk/debug/VehicleRuntimeProbe-debug.apk
adb -s emulator-5554 shell am start -W -n dev.onboard.probe/.ProbeActivity
adb -s emulator-5554 logcat -d -s OnboardRuntimeProbe:I '*:S'
```

최종 실험 APK의 SHA-256은 `63d481b2d6367472f79621d7803b55aa4b8c6db4043879f5eaa5046943c4ada7`이다. 관측 후 `adb -s emulator-5554 uninstall dev.onboard.probe`를 실행해 Success를 확인했다. 진단 소스는 저장소에 남고 APK는 Git 무시 대상인 build 폴더에 있다.

이 코드는 검증용 앱이며 제품 기능이 아니다. 원시 신호는 로컬 logcat에만 출력하며 네트워크 전송·앱의 별도 파일 저장은 하지 않는다. 신규성·사용자 효과·실차 안전성 검증은 별도 미실행이다.

## 확인된 실패와 영향

### SDK-ABI-002: VehicleException 원래 클래스명 부재

공식 소스·참조는 `ai.pleos.playground.vehicle.callback.exception.VehicleException`과 errorCode 속성을 설명한다. 확인한 Vehicle 2.3.2 배포 AAR의 classes.jar에는 해당 클래스 경로가 없고 같은 패키지에 난독화된 예외 클래스가 있다.

해당 import를 사용한 Java 검증 코드를 실제 배포 classes.jar와 함께 javac로 컴파일했을 때 `cannot find symbol: class VehicleException` 오류가 발생했다. 소스의 타입명을 그대로 사용하는 안내는 현재 배포물에서 재현되지 않는다. 이 실패는 Kotlin 런타임 부재가 원인이 아니다. 같은 클래스패스에서 이 import를 제거한 모델 검증은 컴파일·실행됐다.

- 영향: 공식 타입명에 의존한 캐스팅·errorCode 분기 예제를 그대로 적용할 수 없다.
- 문서 조치: API 연동 참조·공통 연결 API·보조 타입 문서에 불일치를 명시했다. 일반 Exception 계약을 유지하고 난독화된 이름을 앱에서 사용하도록 안내하지 않는다.
- 외부 조치 필요: 공개 클래스명이 보존된 수정 배포물 또는 운영사 공식 대응을 확인해야 한다.
- 재검증 조건: 수정 AAR에서 원래 클래스 경로와 errorCode 접근자가 확인되고 import 컴파일이 성공해야 이 항목을 통과로 바꾼다.

### 영역 객체의 순서와 capability 맵 키

6개 구체 영역 타입은 values 배열의 내용과 순서로 동등성·해시를 계산한다. 동일한 영역 집합을 역순으로 생성하면 별도 키가 된다. 이것은 검증 실패가 아니라 확인된 구현 계약이다. capability에서 받은 키를 그대로 사용하고 맵에 넣은 영역의 배열을 수정하지 않는다.

## 재현 자료와 실행 방법

검증 코드는 [ContractProbe.java](../../tools/sdk-contract-probe/ContractProbe.java)에 있다. Android 서비스 인스턴스를 만들지 않고 배포 모델만 실행한다.

실행 전 공식 AAR의 classes.jar를 각각 Vehicle-runtime-classes.jar, FusedLocation-runtime-classes.jar로 준비하고 navi-data의 classes.jar를 navi-data-runtime.jar로 준비한다. Kotlin stdlib와 serialization core/json JVM도 클래스패스에 포함한다. 코드와 바이너리·의존성 버전을 바꾸면 별도 검증 결과로 취급한다.

PowerShell 예시에서 경로는 실제 준비한 자료의 위치로 지정한다. 아래 명령은 바이너리를 자동 다운로드하거나 권한·기기를 설정하지 않는다.

```powershell
$sdkProbeClasspath = @(
  '자료경로/Vehicle-runtime-classes.jar'
  '자료경로/FusedLocation-runtime-classes.jar'
  '자료경로/navi-data-runtime.jar'
  '의존성경로/kotlin-stdlib-2.2.0.jar'
  '의존성경로/kotlinx-serialization-core-jvm-1.6.3.jar'
  '의존성경로/kotlinx-serialization-json-jvm-1.6.3.jar'
) -join ';'
$sdkProbeOutput = Join-Path $env:TEMP 'onboard-sdk-probe'
New-Item -ItemType Directory -Force -Path $sdkProbeOutput | Out-Null
javac -encoding UTF-8 -cp $sdkProbeClasspath -d $sdkProbeOutput tools/sdk-contract-probe/ContractProbe.java
java -cp "$sdkProbeOutput;$sdkProbeClasspath" ContractProbe
```

기대 최종 출력은 `TOTAL 46 passed; no service calls.`다. 모델을 실행할 수 있어도 SDK-ABI-002 실패나 SDK-ENV-001 차단을 통과로 바꾸지 않는다.
