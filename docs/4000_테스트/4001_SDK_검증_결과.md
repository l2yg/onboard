# SDK 검증 결과

## 문서 정보

- 상태: 초안. 확인된 배포물 불일치 1건이 있으며 전체 통과 상태가 아니다.
- 적용 범위: 문서에 수록한 SDK 5종의 공개 진입점·도메인 메서드와 보조 타입. SDK 버전은 API 연동 참조와 동일하다.
- 근거: 2026-10-27 사용자 전체 검증 요청, 공식 배포 AAR·소스 JAR, 로컬 JDK 17 및 Android SDK 환경.
- 관련 요구사항: REQ-CONTEST-001, REQ-CONTEST-009.

## 목적과 범위

기존 추출 목록의 자기 일치 검사와 배포물·실행 결과를 구분한다. 공개 API 이름·오버로드·타입 접근성을 배포 바이너리와 대조하고, Android 서비스 없이 실행 가능한 실제 SDK 모델의 경계·기본값·선택·동등성 계약을 실행한다.

차량 제어, 마이크·오디오 재생, 내비 앱, 위치 서비스, 서버 인증은 실제 Pleos 환경에서만 검증할 수 있다. SDK 서비스 동작을 가짜 결과로 대체하지 않았다. 모델 단위 검증의 통과를 전체 SDK 정상 동작으로 해석하지 않는다.

## 환경과 사전 조건

- JDK 17의 javac/java/javap를 사용했다.
- Vehicle 2.3.2, NaviHelper 3.0.5, FusedLocation 1.1.3, navi-data 3.0.4의 공식 AAR에서 classes.jar를 읽었다. 음성 SDK는 기존에 확보한 3.3.1 AAR 내부 클래스를 사용했다.
- 모델 실행에는 Kotlin stdlib 2.2.0, kotlinx serialization core/json JVM 1.6.3을 사용했다. 이 조합은 이번 JVM 모델 실행의 조건이며 Android 앱의 의존성 권장 버전이 아니다.
- `adb devices -l` 결과 연결된 기기가 없었다. 설치된 AVD는 Pixel_7이며 `google_apis_playstore` 이미지다. 확인한 로컬 Android SDK에는 Pleos AVD가 없어 실제 서비스 검증을 진행하지 못했다.
- 계정 승인·권한·실차 capability와 서버 자격 증명은 확인되지 않았다. 개인 비밀값을 검색하거나 기록하지 않았다.

## 확인된 실패와 영향

### SDK-ABI-002: VehicleException 원래 클래스명 부재

공식 소스·참조는 `ai.pleos.playground.vehicle.callback.exception.VehicleException`과 errorCode 속성을 설명한다. 확인한 Vehicle 2.3.2 배포 AAR의 classes.jar에는 해당 클래스 경로가 없고 같은 패키지에 난독화된 예외 클래스가 있다.

해당 import를 사용한 Java 검증 코드를 실제 배포 classes.jar와 함께 javac로 컴파일했을 때 `cannot find symbol: class VehicleException` 오류가 발생했다. 소스의 타입명을 그대로 사용하는 안내는 현재 배포물에서 재현되지 않는다. 이 실패는 Kotlin 런타임 부재가 원인이 아니다. 같은 클래스패스에서 이 import를 제거한 모델 검증은 컴파일·실행됐다.

- 영향: 공식 타입명에 의존한 캐스팅·errorCode 분기 예제를 그대로 적용할 수 없다.
- 문서 조치: API 연동 참조·공통 연결 API·보조 타입 문서에 불일치를 명시했다. 일반 Exception 계약을 유지하고 난독화된 이름을 앱에서 사용하도록 안내하지 않는다.
- 외부 조치 필요: 공개 클래스명이 보존된 수정 배포물 또는 운영사 공식 대응을 확인해야 한다.
- 재검증 조건: 수정 AAR에서 원래 클래스 경로와 errorCode 접근자가 확인되고 import 컴파일이 성공해야 이 항목을 통과로 바꾼다.

### 영역 객체의 순서와 capability 맵 키

6개 구체 영역 타입은 values 배열의 내용과 순서로 동등성·해시를 계산한다. 동일한 영역 집합을 역순으로 생성하면 별도 키가 된다. 이것은 검증 실패가 아니라 확인된 구현 계약이다. capability에서 받은 키를 그대로 사용하고 맵에 넣은 영역의 배열을 수정하지 않는다.

## 재현 자료와 실행 방법

검증 코드는 [ContractProbe.java](../../tools/sdk-contract-probe/ContractProbe.java)에 있다. Android 서비스 인스턴스를 만들지 않고 배포 모델만 실행한다.

실행 전 공식 AAR의 classes.jar를 각각 Vehicle-runtime-classes.jar, FusedLocation-runtime-classes.jar로 준비하고 navi-data의 classes.jar를 navi-data-runtime.jar로 준비한다. Kotlin stdlib와 serialization core/json JVM도 클래스패스에 포함한다. 코드와 바이너리·의존성 버전을 바꾸면 별도 검증 결과로 취급한다.

PowerShell 예시에서 경로는 실제 준비한 자료의 위치로 지정한다. 아래 명령은 바이너리를 자동 다운로드하거나 권한·기기를 설정하지 않는다.

```powershell
$sdkProbeClasspath = @(
  '자료경로/Vehicle-runtime-classes.jar'
  '자료경로/FusedLocation-runtime-classes.jar'
  '자료경로/navi-data-runtime.jar'
  '의존성경로/kotlin-stdlib-2.2.0.jar'
  '의존성경로/kotlinx-serialization-core-jvm-1.6.3.jar'
  '의존성경로/kotlinx-serialization-json-jvm-1.6.3.jar'
) -join ';'
$sdkProbeOutput = Join-Path $env:TEMP 'onboard-sdk-probe'
New-Item -ItemType Directory -Force -Path $sdkProbeOutput | Out-Null
javac -encoding UTF-8 -cp $sdkProbeClasspath -d $sdkProbeOutput tools/sdk-contract-probe/ContractProbe.java
java -cp "$sdkProbeOutput;$sdkProbeClasspath" ContractProbe
```

기대 최종 출력은 `TOTAL 46 passed; no service calls.`다. 모델을 실행할 수 있어도 SDK-ABI-002 실패나 SDK-ENV-001 차단을 통과로 바꾸지 않는다.

## 미정 사항과 확인 필요 사항

- 배포물 불일치 1건의 운영사 대응과 수정본 재검증.
- 실제 Pleos AVD 또는 연결 기기와 승인된 SDK 권한·서버 자격을 갖춘 환경에서 서비스 호출 검증. 현 로컬 환경만으로 해당 결과를 만들 수 없다.
- 차량별 capability·허용값·주행 제한, 음성 설정·UA 이용 자격, 데이터 단위의 미확인 계약은 동작 계약 검토 문서의 목록을 따른다.
- 대상 환경이 준비되면 정상/미지원/권한 거부/데이터 없음/잘못된 입력/연결 해제·복구/종료 후 재사용과 주행 중 제한을 기능별로 확인한다. 아직 실행하지 않은 시나리오는 통과로 표시하지 않는다.
