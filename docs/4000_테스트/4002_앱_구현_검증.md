# 앱 구현 검증

## 문서 정보

- 상태: 부분 검증 완료. 앱의 기본 사용 흐름과 에뮬레이터 수집을 확인했으며 실차·사용자 효과·배포 심사까지 완료한 상태는 아니다.
- 근거: 2026-10-29 사용자의 완성 앱 구현·전체 검증 요청과 실제 실행 결과.
- 환경: Windows, JDK 21, Gradle 8.13, AGP 8.9.2, Kotlin 2.2.10, compileSdk 35 / targetSdk 34, Vehicle 2.3.2.
- 기기: 기존 `Pleos_Connect_v2.1.0` AVD, Android 14, `emulator-5554`, `crp_avd`. 사용자가 연 기기의 현재 사용자 10에서 최종 기기 시험을 실행했다. 새 Pleos 이미지를 설치하지 않았다.
- 관련 요구사항: REQ-CONTEST-001, REQ-CONTEST-009. TEST-LOST-001의 일부를 확인했으며 TEST-LOST-002·003은 사람 대상 효과 비교가 남아 있다.

## 목적과 범위

빌드 가능 여부뿐 아니라 데이터가 실제로 저장되고 앱 화면의 탐색 과업이 이어지는지를 확인한다. 직접 측정하지 않은 효과·정확도·권한·실차 지원을 테스트 통과로 표시하지 않는다. 테스트는 개발 중인 `dev.onboard.app`의 기록을 초기화하므로 사용자 기록이 있는 환경에서 재실행할 때 주의한다.

기기 시험 전 앱·테스트 APK를 `adb install --no-streaming -r`로 업데이트했다. 초기 Gradle 기기 시험에서 패키지 설치 통신 오류가 발생해 전송 방식을 변경했다. 해당 실패를 성공 건수에 넣지 않았다.

## 실제 기록과 화면 확인

최종 전체 기기 시험 직후 앱 DB를 읽어 초기 알림 `baseline` 6건, `snapshot` 12건, 실제 모드의 정차 방문 1건과 위치 샘플 3건을 확인했다. 해당 방문에 위치가 연결됐고 공급자가 보고한 정확도는 5m였다. 이 숫자는 에뮬레이터의 보고값이며 실제 지리 오차를 측정한 결과가 아니다. 정밀 좌표는 문서에 수록하지 않는다.

화면 시험은 실제·모의 모드 표시, 기억 입력, 복기 목록을 캡처한다. 캡처 파일은 테스트 앱의 비공개 파일에서 회수하며 로컬 `app/build/outputs/device-captures/`에 둔다. 생성 산출물은 Git에 포함하지 않는다. Pleos의 Driving view를 가리지 않고 앱 영역에 표시되는 것을 확인한다.

## 발견한 문제와 수정

- `CAR_SPEED` 권한 미승인으로 정차 판정이 불명인 채 방문이 생성되지 않던 문제: 홈에서 속도 읽기 권한을 요청하고 거부 상태를 안내한다. 테스트에서 임의로 정차 값을 주입해 문제를 숨기지 않았다.
- 권한 요청 후 반드시 특정 시스템 버튼이 나타난다고 가정하던 테스트: Pleos의 즉시 승인 동작을 실제 승인 상태로 검증하도록 수정했다. 미승인을 통과로 바꾸지는 않았다.
- 처음 수신한 문 상태와 반복값을 실제 이동으로 오해할 위험: 별도 종류로 저장하고 변화 건수는 `transition`만 센다. 오류·불명 값 뒤 기준값을 초기화한다.
- 중단 시각을 임의로 채울 위험: 종료 시각을 비워 두고 불명 사유를 표시한다. 수집 이전 이력은 복원하지 않는다.
- 주행 상태 전환 중 열린 상세 대화상자: 정차 확인이 사라지면 닫고 화면도 제한한다. 실제 주행 입력 전환 시험까지 완료한 것은 아니다.
- 기록 중 홈 목록이 갱신되지 않던 처리: 최근 방문 내용이 변하면 홈 목록을 갱신한다. 입력 중인 기억 화면은 매 수신마다 다시 만들지 않는다.

## 남은 검증과 제한

- 실제 문 열림/닫힘 입력에 따른 `transition` 추종, 실제 기어·속도 전환에 따른 화면 제한의 지연은 미검증이다. 이번 실제 문 수신은 초기값과 초기/반복 알림까지다.
- 실차의 위치 공급·권한·도어 영역 지원, 차량 전원 종료·부팅, 장시간 단절과 재연결은 별도 확인이 필요하다. 에뮬레이터에서 앱을 배경으로 보낸 결과만으로 상시 수집을 보증하지 않는다.
- 방문지 목록 대비 시간 절감, 잘못 제외한 장소와 탐색 부담, 지속 이용·사업성은 사람 대상 검증이 남아 있다.
- 앱 전용 SQLite를 사용하지만 별도 DB 암호화·로그인은 없다. 동일 OS 사용자의 다른 차량 사용자가 기록을 볼 수 있다. 앱에서 보관·삭제 정책을 안내한다.
- release APK는 미서명이다. 소유자의 배포 키·applicationId 확정·마켓 심사와 제출용 서명은 미완료다.
