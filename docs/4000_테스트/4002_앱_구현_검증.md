# 앱 구현 검증

## 문서 정보

- 상태: 부분 검증 완료. 앱의 기본 사용 흐름과 에뮬레이터 수집을 확인했으며 실차·사용자 효과·배포 심사까지 완료한 상태는 아니다.
- 근거: 2026-10-29 사용자의 완성 앱 구현·전체 검증 요청과 실제 실행 결과.
- 환경: Windows, JDK 21, Gradle 8.13, AGP 8.9.2, Kotlin 2.2.10, compileSdk 35 / targetSdk 34, Vehicle 2.3.2.
- 기기: 기존 `Pleos_Connect_v2.1.0` AVD, Android 14, `emulator-5554`, `crp_avd`. 사용자가 연 기기의 현재 사용자 10에서 최종 기기 시험을 실행했다. 새 Pleos 이미지를 설치하지 않았다.
- 관련 요구사항: REQ-CONTEST-001, REQ-CONTEST-009. TEST-LOST-001의 일부를 확인했으며 TEST-LOST-002·003은 사람 대상 효과 비교가 남아 있다.

## 목적과 범위

빌드 가능 여부뿐 아니라 데이터가 실제로 저장되고 앱 화면의 탐색 과업이 이어지는지를 확인한다. 직접 측정하지 않은 효과·정확도·권한·실차 지원을 테스트 통과로 표시하지 않는다. 테스트는 개발 중인 `dev.onboard.app`의 기록을 초기화하므로 사용자 기록이 있는 환경에서 재실행할 때 주의한다.

## 실행 결과

### 2026-10-30 키보드 전체 화면 편집 및 작은 입력 글자 수정

- REQ-UX-INPUT-001: 가로 화면에서 CarIME가 작은 추출 편집기를 표시한 문제에 대해 메모 제목·내용·장소 이름에 `IME_FLAG_NO_FULLSCREEN`을 적용했다. 앱 입력 글자는 28sp로 키우고 Activity에는 `adjustResize`를 적용했다.
- `:app:assembleDebug :app:assembleDebugAndroidTest` → 빌드 성공. 기존 Pleos `emulator-5554`에 앱·시험 APK를 갱신하고 사용자 10에서 `AppearanceFlowTest#memoInputKeepsLargeAppFieldsWhileKeyboardIsOpen`을 실행했다. `OK (1 test)`, 6.487초.
- 제목·내용에 시험 문구를 입력하고 메모 화면 표시, 28sp 글자 크기, 전체 화면 방지 옵션과 실제 `InputMethodManager.isFullscreenMode == false`를 확인했다. 시험 문구는 메모로 저장하지 않았다.
- `app/build/outputs/device-captures/memo-input-large.png`를 열어 큰 메모 입력칸과 하단 키보드가 함께 보이는 것을 확인했다. 기존의 작은 전체 화면 추출 편집기는 표시되지 않았다. 장소 이름 팝업·다른 키보드·큰 글자 배율은 별도 시험하지 않았다.

### 2026-10-30 큰 날짜 선택창

- REQ-UX-DATE-001: `MainActivity.chooseDay`의 작은 기본 달력을 큰 날짜 버튼 격자로 교체했다. 확인·취소는 최소 144dp 폭과 16dp 간격을 적용하고 확인 버튼에 강조 배경을 사용한다.
- `:app:assembleDebug :app:assembleDebugAndroidTest` 성공. 기존 Pleos `emulator-5554`에 앱·테스트 APK 갱신 후 사용자 10에서 `AppearanceFlowTest#datePickerHasLargeTargetsAndSupportsMonthNavigation`을 실행했다. 최종 `OK (1 test)`, 5.993초.
- 날짜 버튼 폭·높이 최소 80dp, 글자 24sp 이상, 확인 버튼 폭 120dp 이상, 이전·다음 달 이동과 선택 적용을 확인했다. 최신 `app/build/outputs/device-captures/date-picker-large.png`를 열어 선택 표시·버튼 간격과 화면 배치를 확인했다.
- 첫 시험은 정차 신호 확인 전에 열기 버튼을 눌러 달력이 열리지 않아 실패했다. 시험이 화면의 방문 조회 가능 상태를 기다리도록 바꾼 뒤 통과했다. 정차 제한은 유지했다.
- 큰 글자 배율·좁은 화면·다크 모드의 새 달력은 별도 기기 검증하지 않았다. 해당 설정을 반영하는 구현과 기본 배율에서의 실제 확인을 구분한다.

### 2026-10-30 주소·내비 오류 수정 후 재검증

- 원인: Android GPS는 미국 기본 좌표(37.421998, -122.084000), Pleos 내비는 한국 현재 위치를 사용했다. 시스템 Geocoder 구현도 없었다. 기존 에뮬레이터의 시험 GPS를 내비의 한국 현재 위치로 맞췄으며 과거 저장 좌표는 수정하지 않았다.
- 변경: Pleos 내비 현재 주소의 100m 이내 대체 조회·기록 중 주소 저장, 요청 좌표와 표시 좌표 전달, 목적지 일치와 `NaviMode.ROUTE_GUIDING` 확인, 최대 30초 상태 확인, 내비 오류 분류와 앱 복귀 안내를 추가했다.
- 빌드: `:app:assembleDebug :app:assembleDebugAndroidTest` 성공. 최신 앱·테스트 APK를 기존 `emulator-5554`에 `install --no-streaming -r`로 갱신했다. 단위 시험은 수정 중 `:app:testDebugUnitTest`를 실행해 12건 통과를 확인했다.
- 최종 기기 회귀: `am instrument --user 10 -w -e class dev.onboard.app.PleosAddressTest,dev.onboard.app.PleosRouteTest,dev.onboard.app.HistoryStoreTest dev.onboard.app.test/androidx.test.runner.AndroidJUnitRunner` → `OK (13 tests)`, 14.286초. 주소 대체 조회·기존 방문 보존을 포함한 수집 중 주소 저장 2건, 실제 한국 경로 생성·목적지 일치 확인 1건, DB·주소 저장 회귀 10건이다. 최종 실행에 건너뜀은 없었다.
- 시각 관측: 한국 시험 목적지 요청 뒤 실제 내비에 회전 안내, 도로 경로, 2.2km·9분이 표시됐다. `app/build/outputs/device-captures/route-after-fix.png`에 캡처했다. 이 캡처와 최종 자동 시험의 목적지 좌표는 서로 다른 한국 시험 지점이며 효과 수치 비교가 아니다.
- 앱 갱신 후 실제 방문 목록에서 내비가 제공한 `수정구 시흥동` 주소 표시를 확인했다. `app/build/outputs/device-captures/address-after-fix.png`에 캡처했다. 제공자가 준 동 단위 주소이며 상세 도로명·건물 주소를 확인했다는 뜻은 아니다.
- 중간 실패: 처음에는 경로가 실제 생성돼도 `onRoutingCompleted`만 기다려 30초 시간 초과가 났다. 활성 경로·목적지 조회를 추가하고 실제 안내 모드로 판정을 수정한 뒤 통과했다. 중간 실패를 성공 건수에 포함하지 않는다.
- 제한: Geocoder 자체는 여전히 미지원이며 Pleos 주소를 대체 사용한다. 내비 주소는 현재 위치에 대한 정보이므로 100m 밖의 과거 방문에는 붙이지 않는다. 잘못 저장된 미국 시험 좌표는 원본대로 남는다. 이 결과는 에뮬레이터 검증이며 실차·임의 지역·네트워크 단절까지 보장하지 않는다.

아래 최신 자동 검증 절은 이번 수정 전의 관측을 보존한 내용이며, 해결 상태는 이 절을 우선한다.

내비 로그에는 `boundary_check: FailToSetStartPoint`와 응답 `resultCode:500`, `RouteResponse(resultCode=202)`가 관측됐다. 내비의 출발점 설정 실패가 보이지만 네트워크·지도·좌표 중 근본 원인을 확정하지 않았다. 앱은 내비의 비동기 `onError`를 별도로 처리하지 않아 요청 직후 메시지와 최종 성공·실패를 구분하는 처리가 남아 있다.

현재 해결되지 않은 연결 범위는 시스템 Geocoder가 없는 환경의 실제 주소 제공 방식과 내비 경로 생성 실패다. 실제 이동·문 개방·실차 전원 변화는 이번 정차 시험으로 검증하지 않았다. 이전의 미실행 기록은 당시 상태이며, 이 절이 최신 결과다.

### 정차 주소 표시와 길 안내 UI: 빌드·앱 갱신 완료

- 2026-10-30 최신 후속 변경: 길 안내는 목록에 유지하고 상세의 중복 버튼을 제거했다. 상세의 복기·메모·위치·차량 기록 버튼에 각각 위쪽 16dp 여백을 적용했다. 예시 주소와 좌표 없는 실제 방문의 안내 불가 설명은 유지한다.
- 사용자 앱 갱신 요청에 따라 `:app:assembleDebug --console=plain`을 실행해 `BUILD SUCCESSFUL`을 확인했다. 기존 `emulator-5554`에 `adb install --no-streaming -r`로 설치해 `Success`를 확인하고 사용자 10에서 앱을 시작했다. 자동 테스트·최신 화면 캡처·실제 내비 경로 생성은 확인하지 않았다.

- REQ-VISIT-ADDRESS-001: 이름 우선순위·주소 저장·이전 좌표 응답 거부·DB v5 업그레이드 보존 사례를 `HistoryStoreTest`에 추가했다.
- 주소 기능의 자동 테스트·Pleos 주소 조회 성공은 확인하지 않았다. 기존 테스트 통과 결과는 이번 주소 기능의 통과 근거가 아니다.
- 기기에 Geocoder 구현이 없거나 네트워크·제공자 응답이 없을 때 주소가 표시되지 않는 것은 허용된 동작이다. 실제 주소 조회 성공과 화면 배치는 기기 검증이 남아 있다.

## 실제 기록과 화면 확인

- `:app:assembleDebug`, `:app:assembleDebugAndroidTest`: 성공. 기존 deprecated API·Gradle 경고는 남아 있다. 이전 시험 APK의 화면 흐름·모드·접근성 치수 시험으로 새 표시 이름까지 확인한다.
- 기본 본문 22sp·버튼 24sp/80dp, 시스템/라이트/다크 선택과 실제/연습 데이터 분리를 유지한다. 버튼 경계 대비를 보완하고 날짜·방문·설정·메모 화면을 기존 Pleos의 캡처로 확인한다. 추가 화면 크기·글자 200%·실차 자동 모드·실제 고령 사용자 과제 수행은 이번 검증에 포함하지 않는다.

## 상단 메뉴·방문 이력 화면 전면 교체 검증 · 2026-10-29

- 사용자 선호는 ‘완성도 높은 차량 앱 같은 고급스러움’이다. 기존 녹색·사이드바·방문별 카드 배경을 폐기하고 흰색/먹색/파랑, 상단 메뉴, 한 장의 기록 면과 행 정렬로 교체했다. 야간은 중성 바탕과 밝은 파랑을 사용한다. 이전 절의 녹색 화면 캡처는 과거 상태다.
- `:app:assembleDebug`, `:app:assembleDebugAndroidTest`: 성공. 첫 기기 실행에서 초기 메뉴 터치와 정차 확인 갱신이 겹쳐 모드 화면 이동이 실패했다. 터치가 끝나도 Android 클릭 처리가 완료되기 전에 화면을 다시 만들지 않도록 비안전성 갱신에 150ms 지연을 두었다. 주행/불명으로 조작을 제한하는 갱신은 즉시 유지한다.
- 최종 앱 빌드·업데이트 후 기존 Pleos 사용자 10에서 `adb shell am instrument --user 10 -w -e class dev.onboard.app.AppFlowTest,dev.onboard.app.AppearanceFlowTest dev.onboard.app.test/androidx.test.runner.AndroidJUnitRunner`: `OK (3 tests)`, 모두 통과했다. 본문·버튼 크기, 날짜 선택, 방문부터 복기, 메모 유지·수정·삭제, 라이트/다크/시스템 전환을 확인했다. 색 리소스 기대값도 새 테마에 맞췄다.
- `app/build/outputs/device-captures/`의 최종 홈·설정·메모·복기 캡처를 에뮬레이터에서 다시 생성해 확인한다. 실패한 모드 시험 이전에 남아 있던 캡처를 새 결과로 취급하지 않는다. 저장·수집·단위·release·lint는 이번 UI 변경에서 재실행하지 않았다. 추가 화면 크기·글자 200%·실차·실제 고령 사용자 평가도 별도다.

## 남은 검증과 제한

- 실제 문 열림/닫힘 입력에 따른 `transition` 추종, 실제 기어·속도 전환에 따른 화면 제한의 지연은 미검증이다. 이번 실제 문 수신은 초기값과 초기/반복 알림까지다.
- 실차의 위치 공급·권한·도어 영역 지원, 차량 전원 종료·부팅, 장시간 단절과 재연결은 별도 확인이 필요하다. 에뮬레이터에서 앱을 배경으로 보낸 결과만으로 상시 수집을 보증하지 않는다.
- 방문지 목록 대비 시간 절감, 잘못 제외한 장소와 탐색 부담, 지속 이용·사업성은 사람 대상 검증이 남아 있다.
- 앱 전용 SQLite를 사용하지만 별도 DB 암호화·로그인은 없다. 동일 OS 사용자의 다른 차량 사용자가 기록을 볼 수 있다. 앱에서 보관·삭제 정책을 안내한다.
- release APK는 미서명이다. 소유자의 배포 키·applicationId 확정·마켓 심사와 제출용 서명은 미완료다.
