# 차량 서비스 연결 API

## 문서 정보

- 상태: 초안.
- 적용 범위: Vehicle SDK의 Vehicle 메서드 21개 이름과 해당 오버로드.
- 근거: 2026-10-27 조사한 공식 API 문서·릴리스 노트·배포 선언. 개별 출처는 본문에 명시한다.
- 관련 요구사항: REQ-CONTEST-001, REQ-CONTEST-009. 제공 기능의 조사이며 제품의 채택·구현 완료를 뜻하지 않는다.

## 목적과 범위

이 영역의 공개 기능과 입력·콜백 출력·권한·폐기 여부를 확인한다. 다른 영역과의 공통 정책은 상위 문서에서 관리한다. 연결·조회·제어·리스너를 포함하며 SDK 내부 구현과 자동 생성 보일러플레이트는 제외한다.

## 동작 의미와 제한

- `Vehicle(context)`를 생성하고 앱 생성 시 `initialize()`, 사용 종료 시 `release()`를 호출한다. 19개 `getXxx()`는 도메인 객체를 얻는 진입점이며 차량 상태값을 즉시 읽는 API가 아니다.
- 연결은 비동기다. `initialize()` 반환만으로 서비스 연결·capability 로드가 끝났다고 간주하지 않는다.
- `checkXxxCapabilities`의 `AccessType`으로 읽기/쓰기 지원을 구분하고 별도 영역 목록·범위·허용값을 사용한다. 조회 실패와 `NONE`은 같은 결과가 아니다.
- 영역의 `vararg values`는 비트 OR로 묶인다. 빈 영역은 INVALID가 되며 조회·제어에서 실패한다. 영역을 여러 개 표현할 수 있어도 모든 메서드가 복수 영역을 허용하는 것은 아니다.
- 조회/제어 실패는 일반 `Exception`일 수도 있다. 확인한 Vehicle 2.3.2 AAR에서 `VehicleException`의 원래 클래스명이 없어 소스의 타입을 직접 import·캐스팅할 수 없는 배포물 불일치가 확인됐다. 승인된 수정 배포물을 확인하기 전에는 `Exception` 계약으로 처리한다. 리스너 등록·해제의 권한 검사에는 동기 예외 경로가 있다.
- 영역 모델의 동등성·해시 계산은 `values`의 순서를 구분한다. 같은 비트 집합이어도 역순으로 만든 영역 객체는 capability 맵의 다른 키가 될 수 있으므로 반환된 영역 키를 그대로 사용한다. 배열 내용을 바꾸면 해시값도 달라질 수 있으므로 맵 키로 사용하는 동안 변경하지 않는다.
- 콜백은 Binder/코루틴 경로로 전달되며 모든 콜백의 메인 스레드 실행을 보장하지 않는다. 제어 성공 콜백에는 요청값을 되돌려 주는 구현이 있으므로 실제 상태 변화는 조회·리스너로 구분한다.

## 미정 사항과 확인 필요 사항

실제 계정 승인, 차종별 지원 영역·허용 값·주행 중 제한과 실차 동작은 미검증이다. 공개 문서·배포 선언에서 확인하지 못한 입력 의미·기본값·동작 보장은 추정하지 않는다. SDK 선택과 구체적인 제품 기능은 미정이며 개요 문서의 제공 상태·제약을 함께 확인한다.
