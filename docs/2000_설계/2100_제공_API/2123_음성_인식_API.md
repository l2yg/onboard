# 음성 인식 API

## 문서 정보

- 상태: 초안.
- 적용 범위: SpeechToText SDK의 SpeechToText 메서드 10개 이름과 해당 오버로드.
- 근거: 2026-10-27 조사한 공식 API 문서·릴리스 노트·배포 선언. 개별 출처는 본문에 명시한다.
- 관련 요구사항: REQ-CONTEST-001, REQ-CONTEST-009. 제공 기능의 조사이며 제품의 채택·구현 완료를 뜻하지 않는다.

## 목적과 범위

이 영역의 공개 기능과 입력·콜백 출력·권한·폐기 여부를 확인한다. 다른 영역과의 공통 정책은 상위 문서에서 관리한다. 연결·조회·제어·리스너를 포함하며 SDK 내부 구현과 자동 생성 보일러플레이트는 제외한다.

## 동작 의미와 제한

- 초기화·리스너 등록 후 `request()`가 차량 마이크 인식을 시작한다. 서버 기반 인식은 일반 `registerApp`의 연결 성공 이후 사용한다. `stop()`은 인식과 마이크 사용을 종료하며 `onEndedRecognition()`을 받는다.
- 기본 모드는 HYBRID다. SERVER는 자동 오프라인 전환하지 않고 ON_DEVICE는 서버 앱 등록 없이 사용한다. 추가 `registerApp` 두 오버로드는 바이트코드상 각각 `(uaAppId, uaAppKey, uaAppName, onSuccess, onFail)`과 `(uaAppCode, onSuccess, onFail)`을 받아 UA 경로를 활성화한다. 이용 자격·발급 절차·서버 동작은 미확인이다.
- `sendAudio` 입력은 JVM의 primitive byte 배열 `[B`, Kotlin의 `ByteArray`다. boxed 배열인 `Array<Byte>`가 아니다. 앱 보유 PCM을 전체/청크로 보내는 ON_DEVICE 전용 경로이며 마지막에 `completeAudioSend()`가 필요하다.
- `sendAudio`는 바이트코드상 ON_DEVICE 외 모드에서는 오류 로그를 남기고 전송하지 않는다. 이 분기에서 오류 콜백을 호출하지 않으므로 `NOT_SUPPORTED_API`를 항상 받을 것으로 가정하지 않는다.
- 가이드의 3,200바이트·100ms는 16kHz/16-bit/mono PCM 예제다. 모든 환경에서 허용되는 고정 형식·청크 크기라는 뜻은 아니다.
- `onUpdated(stt, completed)`의 true는 해당 인식 결과 완료다. 중간 텍스트와 최종 텍스트, 세션 종료를 구분한다.
- `onUpdatedEpdData(on, off)`는 오디오 버퍼의 바이트 오프셋이다. ms·초가 아니다. `onUpdatedRms`는 신호 크기이며 dB가 아니다.
- `setLocale`는 다음 인식 요청에 적용된다. 미설정 시 같은 앱의 이전 설정, 없으면 시스템 Locale을 사용한다. STT 가이드에서도 ko-KR/en-US/fr-CA/es-US/es-MX를 별도로 확인했다.
- 리스너는 `request/sendAudio` 전에 등록하고 동일 인스턴스로 제거한 뒤 `release()`한다. 해제 후 재사용은 새 객체 생성·초기화 절차를 따른다.
- `ErrorType`으로 입력 오디오/마이크/권한/인증/네트워크/엔진/언어/미지원 상태를 구분한다. 인식 텍스트가 앱 기능이나 차량 제어를 직접 실행하지 않는다.
- 공개 진입점의 각 void 메서드는 서비스 권한을 먼저 검사하며 미승인 시 동기 `SecurityException`을 던지는 바이트코드를 확인했다. 초기화·리스너 등록과 해제도 이 검사 대상이다.

## 미정 사항과 확인 필요 사항

실제 계정 승인, 차종별 지원 영역·허용 값·주행 중 제한과 실차 동작은 미검증이다. 공개 문서·배포 선언에서 확인하지 못한 입력 의미·기본값·동작 보장은 추정하지 않는다. SDK 선택과 구체적인 제품 기능은 미정이며 개요 문서의 제공 상태·제약을 함께 확인한다.
