# 공조 API

## 문서 정보

- 상태: 초안.
- 적용 범위: Vehicle SDK의 HVAC 메서드 67개 이름과 해당 오버로드.
- 근거: 2026-10-27 조사한 공식 API 문서·릴리스 노트·배포 선언. 개별 출처는 본문에 명시한다.
- 관련 요구사항: REQ-CONTEST-001, REQ-CONTEST-009. 제공 기능의 조사이며 제품의 채택·구현 완료를 뜻하지 않는다.

## 목적과 범위

이 영역의 공개 기능과 입력·콜백 출력·권한·폐기 여부를 확인한다. 다른 영역과의 공통 정책은 상위 문서에서 관리한다. 연결·조회·제어·리스너를 포함하며 SDK 내부 구현과 자동 생성 보일러플레이트는 제외한다.

## 공조 호출 시 확인할 계약

아래 의미는 Vehicle 2.3.2의 `HVAC.kt`와 온도 리스너·모델 선언을 직접 확인한 내용이다. 메서드 서명에 표시된 타입만으로 단위와 값의 의미를 판단하지 않는다.

- 조회·지원 확인·리스너 등록/해제는 `CAR_CLIMATE`, 제어는 `CONTROL_CAR_CLIMATE` 권한을 사용한다. Manifest 이름은 각각 `pleos.car.permission.CAR_CLIMATE`, `pleos.car.permission.CONTROL_CAR_CLIMATE`다.
- `SeatArea(vararg values: SeatValue)`는 하나 이상의 좌석 영역을 표현할 수 있는 입력 모델이다. 실제 지원 영역은 capability 응답으로 확인한다. 성에 제거의 영역 타입은 `WindowArea`이므로 좌석 영역과 혼용하지 않는다.
- `getHvacTemperature`는 설정 목표 온도, `getHvacTemperatureCurrent`는 현재 실내 온도다. 후자의 `unit` 없는 오버로드는 섭씨(°C), `unit` 있는 오버로드는 요청한 단위로 반환한다.
- `checkHvacTemperatureCapabilities`의 최신 오버로드는 `CapabilityConfig`, 영역별 `AreaBounds<Float>`, 선택적인 `HvacTemperatureConfigArray`를 반환한다. 최소·최대값은 `CapabilityConfig`가 아닌 영역별 `AreaBounds`에 있으며 단위는 섭씨다. 차량별 범위이므로 고정 온도 범위를 가정하지 않는다.
- `HvacTemperatureConfigArray`의 온도·증가 간격 속성은 섭씨/화씨의 실제 `Float` 값이다. `raw`는 온도·간격에 10을 곱한 원본 정수 6개다. 화씨 변환에는 차량별 설정표를 확인한다.
- `setHvacTemperature`의 `value`와 성공 콜백의 온도는 요청한 `unit` 기준이다. 성공 콜백은 설정 성공 후 요청한 목표 온도를 전달하며 실내 온도가 그 값에 도달했다는 의미는 아니다.
- `HvacTemperatureListener`는 섭씨 값 하나를 전달한다. `registerHvacTemperature`로 등록하면 목표 온도, `registerHvacTemperatureCurrent`로 등록하면 현재 실내 온도이며, 값이 없으면 `null`이다.
- `HvacTemperatureValueListener`는 섭씨·화씨 값을 함께 전달한다. 화씨는 차량별 변환 규칙을 우선하고 없으면 공식 변환으로 대체한다. 목표/현재 온도의 구분은 등록한 메서드를 따른다.
- `registerHvacAutoRecirculationState`의 리스너 타입은 소스상 `HvacRecirculationStateListener`다. 이름이 비슷하다는 이유로 다른 리스너 타입을 만들지 않는다.

## 메서드 정의

에어컨, 공기청정, 자동 공조, 자동 내기순환, 성에 제거, 듀얼, 풍향, 풍량, 최대 냉방, 최대 성에 제거, 공조 전원, 내기순환, 설정 온도, 현재 온도. 현재 온도는 조회/알림이며 나머지는 항목별 조회·제어·알림·지원 확인 범위가 다르다. 풍향 변경 알림 메서드는 목록에서 확인하지 못했다.
