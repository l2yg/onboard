# 위치 API

## 문서 정보

- 상태: 초안.
- 적용 범위: FusedLocation SDK의 FusedLocation 메서드 9개 이름과 해당 오버로드.
- 근거: 2026-10-27 조사한 공식 API 문서·릴리스 노트·배포 선언. 개별 출처는 본문에 명시한다.
- 관련 요구사항: REQ-CONTEST-001, REQ-CONTEST-009. 제공 기능의 조사이며 제품의 채택·구현 완료를 뜻하지 않는다.

## 목적과 범위

이 영역의 공개 기능과 입력·콜백 출력·권한·폐기 여부를 확인한다. 다른 영역과의 공통 정책은 상위 문서에서 관리한다. 연결·조회·제어·리스너를 포함하며 SDK 내부 구현과 자동 생성 보일러플레이트는 제외한다.

## 동작 의미와 제한

- `initialize`가 서비스를 연결하고 `release`는 위치 리스너·근접 알림을 정리한다. `isSupported`는 서비스 패키지 조회 성공 여부이며 초기화·연결·권한·위치값 가용성을 확인하지 않는다.
- `getLastKnownLocation`는 마지막 계산 위치를 콜백으로 받고 `null`일 수 있다. `registerFusedLocationCallback`은 지속 변경 수신, `unregisterFusedLocationCallback`은 해당 리스너 해제다.
- 위치 조회·등록/해제·근접 알림은 dangerous 권한 `pleos.car.permission.FUSED_LOCATION`을 요구한다. 미승인은 콜백 이전 동기 `SecurityException`이므로 오류 콜백만 처리해서는 부족하다.
- 근접 요청은 유한한 위도 -90~90, 경도 -180~180, 양수 반경(m), 비어 있지 않은 ENTER/EXIT 집합이어야 한다. 입력 오류는 리스너 `onError`, 등록 성공은 `onRegistered(alertId)`, 진입/이탈은 `onTransition`이다.
- `removeProximityAlert`는 권한을 먼저 확인하고 알 수 없거나 이미 제거된 ID는 무시한다. 원격 제거 실패를 앱 성공 콜백으로 알리는 API는 없다.
- 서비스 재연결 시 기존 위치 콜백과 이미 전송된 근접 등록을 재등록하는 구현이 있다. 프로세스 재시작·차량 재시동 이후 지속성까지 보장하는 것은 아니다.
- `showLocationAccessBlockedPopup`는 개인정보 설정 때문에 차단됐다는 안내 화면 요청이다. 권한 승인·차단 해제를 자동 수행하지 않는다.
- `LocationData.confidence`의 단위·의미, altitude/heading의 세부 기준과 수신 주기·백그라운드 유지 정책은 선언만으로 확정할 수 없다. 다른 위치 SDK의 계약을 가져오지 않는다.

## 미정 사항과 확인 필요 사항

실제 계정 승인, 차종별 지원 영역·허용 값·주행 중 제한과 실차 동작은 미검증이다. 공개 문서·배포 선언에서 확인하지 못한 입력 의미·기본값·동작 보장은 추정하지 않는다. SDK 선택과 구체적인 제품 기능은 미정이며 개요 문서의 제공 상태·제약을 함께 확인한다.
