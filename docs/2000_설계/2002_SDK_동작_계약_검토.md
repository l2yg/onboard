# SDK 동작 계약 검토

## 문서 정보

- 상태: 초안. 정적 계약 검토이며 실제 SDK 실행 통과 기록이 아니다.
- 적용 범위: Vehicle 2.3.2, NaviHelper 3.0.5 및 navi-data 3.0.4, TextToSpeech 3.3.1, SpeechToText 3.3.1, FusedLocation 1.1.3.
- 근거: 2026-10-27 내려받은 공식 소스 JAR·음성 SDK AAR, 공식 프로그래밍 가이드와 공개 참조. 아래 근거 자료와 각 상세 문서의 출처를 따른다.
- 정적 분석 방법: 소스 선언·KDoc·구현 경로를 읽고, 음성 SDK는 JDK 17의 `javap -p -c`로 AAR 내부 클래스의 권한 검사·위임·모드 분기를 확인했다. SDK 클래스를 실행하거나 차량/서버를 호출하지 않았다.
- 관련 요구사항: REQ-CONTEST-001, REQ-CONTEST-009. 제품의 SDK 채택·차량 제어 권한 승인을 뜻하지 않는다.

## 목적과 범위

메서드 개수 대조를 넘어 입력 의미·단위·허용 범위·지원 여부·결과 전달 방식·오류·수명주기를 검토한다. 기존 추출 JSON과 Markdown이 일치한다는 사실만으로 의미가 검증됐다고 판단하지 않는다.

정적 자료가 설명하지 않는 서비스 동작은 미확인으로 남긴다. 모든 메서드의 실차 동작까지 검증한 상태는 아니다. SDK 내부 구현 전체의 결함 검증이나 서버·차량 서비스의 구현 감사는 범위 밖이다.

소스가 있는 3종은 총 551개 호출 선언을 실제 JAR에서 재추출해 기존 정의의 서명·오버로드별 폐기 어노테이션과 대조했다. 음성 2종의 27개 선언은 ABI를 대조한 뒤 가이드와 바이트코드를 함께 검토했다. ABI·바이트코드만으로 서비스 측 동작과 공식 이용 자격까지 확인할 수는 없다. 안내서가 없는 오버로드는 일반 앱 권장 사용법으로 확대하지 않는다.

530개는 공개 진입점·도메인의 메서드명 수다. 모델의 보조 메서드나 생성자까지 모두 합친 SDK 전체 메서드 수가 아니다. 예를 들어 `TripStatistics.get(type)`은 보조 타입 문서에서 관리한다.

## SDK 간 공통으로 오해하기 쉬운 계약

- `Unit` 반환·초기화 함수 반환은 비동기 작업의 완료가 아니다. 초기화/서비스 연결/요청 접수/상태 변화/물리 동작 완료를 구분한다.
- nullable 결과는 실패 콜백과 별개일 수 있다. `null`을 0·false·정상 상태로 변환하지 않는다.
- 권한이 없을 때 모든 API가 오류 콜백만 호출하는 것은 아니다. Vehicle 리스너 경로, NaviHelper·FusedLocation에는 호출 시 동기 예외 경로가 있다.
- 음성 SDK도 공개 void 메서드의 진입점에서 서비스 권한을 동기 검사한다. STT `sendAudio`의 잘못된 모드는 로그만 남기고 전송하지 않는 분기가 있어 오류 이벤트만 기다리면 실패를 놓칠 수 있다.
- 실패가 항상 같은 Exception 하위 타입·숫자 오류 코드로 전달되지는 않는다. 원래 예외와 메시지를 보존한다.
- 콜백 주기·순서·상관 ID·동시 요청 처리·메인 스레드 전달·타임아웃·재시도의 공통 보장은 확인되지 않았다. 제품 설계 시 필요한 조건을 별도로 정하고 대상 환경에서 확인한다.
- 모델이 존재하거나 capability가 읽힌다는 사실만으로 실차 값·기능·승인이 보장되지 않는다. 서비스 권한과 기획 기능의 승인은 별도다.

## 확인된 정정과 충돌

| 항목 | 정정·판단 |
| --- | --- |
| STT `sendAudio` | JVM `[B`는 Kotlin `ByteArray`다. 기존의 `Array<Byte>` 표기를 수정했다. |
| STT EPD / RMS | EPD는 입력 버퍼 바이트 오프셋, RMS는 신호 크기다. 시간 단위·dB로 해석하지 않는다. |
| 음성 권한·모드 오류 | 공개 메서드 진입점의 동기 권한 예외와 STT sendAudio의 잘못된 모드 무전송 분기를 바이트코드로 확인했다. |
| 추가 음성 앱 등록 | 바이트코드에서 UA 입력 이름·분기까지 확인했다. 공개 서비스 이용 자격은 별도 확인 대상이다. |
| 음성 locale·수명주기 | STT도 독립적으로 지원 언어를 확인했다. 해제 후 새 객체를 생성해 초기화하는 가이드와 이전 설정 우선 동작을 반영했다. |
| EV/Fuel 순간 효율 | 향후 폐기 설명과 현재 `@Deprecated` 부착 여부를 구분했다. |
| EV 설정 성공 인자 | 일부 KDoc의 Float 설명과 달리 충전구·충전 스위치의 선언·구현은 Boolean이다. |
| 조명 스위치 조회 | 일부 KDoc의 LightState 설명과 달리 스위치 조회 선언·구현은 LightSwitch다. |
| 시트 헤드레스트 각도 조회 | KDoc의 이동 콜백 문구와 달리 서명은 Int 위치 조회다. |
| 안전 에어백 활성 | 이름·설명 충돌이 남는다. 단순 Boolean 매핑 구현은 true 의미의 근거가 되지 않는다. |
| 영역 모델 | 7종 영역 생성자·values 속성과 Area 기반 타입을 원본 소스로 확인했다. |
| 영역 모델 동등성 | 6개 구체 영역 타입은 values의 순서가 다르면 서로 다른 맵 키가 된다. JVM 실행으로 확인했다. |
| VehicleException 배포 | 소스·문서에는 있으나 확인한 2.3.2 AAR에서 원래 이름이 없어 직접 import 컴파일이 실패했다. SDK 배포물 확인이 필요하다. |
| 내비 화면 요청 | 중첩 변형의 필드를 기반 타입 공통 속성처럼 표시하던 표를 수정하고 POI 제공자·기본값을 보완했다. |
| TripStatistics | 모델의 `get(type)` 조회와 기본값을 보완했다. |

| FusedLocation 필드 | confidence, altitude/heading의 단위·좌표/기준 정의 부족 | 동버전 서비스 데이터 계약 |
| 차량별 영역·단계·범위 | 정적 모델·capability 인터페이스 확인 | 실제 차종의 capability 응답과 승인 권한 |
| 음성 PCM·성능 | 가이드 예제만 확인. 모든 형식 지원을 보장하지 않음 | 대상 환경의 허용 형식·길이·지연·동시 요청 제한 |
| 실제 서비스 상태 변화 | SDK 요청·응답/이벤트 경로 확인 | 승인된 계정·에뮬레이터/실차에서 정상·오류·미지원·권한 거부·해제/재연결 실행 |

위 미확인 계약이 남아 있으므로 '전체 SDK 동작 의미 검증 완료'로 표시하지 않는다. 정적 검토에서 확인된 내용은 반영했으며, 외부 근거가 없는 계약은 제품의 보장 기능으로 확정하지 않는다.

전체 배포 ABI 대조·모델 46건 실행·문서 구조 점검과 실제 실행 환경 확인 결과는 테스트 분류의 [SDK 검증 결과](../4000_테스트/4001_SDK_검증_결과.md)에서 관리한다. 이 문서는 계약 해석을 유지하며 실행 결과의 원본을 중복 관리하지 않는다.
