# 방문 이력 복기 구현

## 문서 정보

- 상태: 초안. 주제 유지·자동 기록 우선 검증은 확정이며, 아래 구성과 세부 구현은 계획이다.
- 근거: 2026-10-29 사용자의 구현 계획 정리 요청, DEC-LOST-001.
- 적용 범위: 기존 Kotlin 앱과 별도 진단 앱을 활용한 기술 확인, 최소 제품, 효과 비교, 시연 준비.
- 관련 요구사항: REQ-CONTEST-001, REQ-CONTEST-006, REQ-CONTEST-009. 제품의 전체 기능 요구사항·설계는 아직 미작성이다.

## 목적과 범위

### 정차 주소 표시 (REQ-VISIT-ADDRESS-001)

- 사용자 요청: 좌표를 주소로 표시하고 직접 붙인 장소 이름을 우선한다. 목록·상세·메모의 방문 이름·내비 요청 이름에 같은 우선순위를 적용한다.
- DB v6에서 주소와 조회 당시 좌표를 기존 방문에 추가한다. 원래 이름·좌표·메모는 보존한다. 화면에 표시하는 실제 방문의 주소가 없으면 비동기 조회하며 모의 방문은 조회하지 않는다.
- Android 33 이상은 Geocoder 비동기 콜백, 이전 버전은 별도 작업 스레드를 사용한다. 동시 요청은 2개, 응답 대기는 15초, 같은 화면 인스턴스의 동일 방문 재시도 간격은 10분이다. 성공한 주소는 기기에 저장한다.
- 이름 우선순위는 직접 붙인 이름 → 좌표 기준 주소 → `정차 장소`이다. 주소를 가져오지 못해도 시각·좌표·이름 직접 입력을 유지한다. 매장 방문을 자동 확정하지 않는다.
- 조회 좌표와 현재 방문 좌표가 100m 넘게 다르면 이전 주소를 표시하거나 늦은 응답을 저장하지 않는다. 삭제·만료된 방문의 응답도 저장하지 않으며 ID와 시작 시각을 함께 비교한다.
- 자체 서버는 없으나 시스템 주소 제공자와의 통신이 발생할 수 있어 시작 동의와 보관 안내에 명시한다. 기기의 Geocoder 구현·연결 상태에 따라 주소는 제공되지 않을 수 있다.
- API 근거: [Android Geocoder 공식 문서](https://developer.android.com/reference/android/location/Geocoder), 2026-10-29 확인. 현재 도구에 Context7은 제공되지 않아 공식 문서를 확인했다. 빌드·기기 조회 검증 상태는 [앱 구현 검증](../4000_테스트/4002_앱_구현_검증.md)에 기록한다.

**현재 적용 범위(2026-10-29 최신 사용자 결정): 앱은 차량 방문 이력 복기와 방문 메모로 개편한다. 아래 초기 분실물 구현 단계·UX 이력은 과거 상태이며, 물건 찾기는 출품 기획의 활용 시나리오에만 남긴다.**

- 방문 기록: 최근 7일/날짜 필터, 최근 5곳/저장 목록 펼치기, 방문에서 바로 시간순 복기 시작. 복기 기준 이후의 방문과 날짜 범위에 겹치는 위치 누락 경고를 구분한다.
- 방문 상세: 정차 시각·위치·내비 정보, 방문 메모, 해당 방문 전까지 실제 수집한 위치(최근 50건), 별도 요청으로 차량 원시 정보 확인. 지도·도로 경로 재구성은 제공하지 않는다.
- 메모: 방문에 연결하거나 일반 메모로 작성하고 제목·내용을 수정/삭제한다. DB 버전 4에서 별도 테이블을 추가하며 기존 원시 자료와 이전 버전 자료는 삭제하지 않는다. 방문 보관 기간이 지나면 메모의 방문 연결을 해제하여 새 방문 ID에 잘못 연결되지 않게 한다.
- 실제/모의 기록 분리, 로컬 보관·전체 삭제, 입력 중 이탈 확인, 정차 제한과 시스템/라이트/다크 설정을 유지한다. 물건 등록·관련 문 선택·찾음/미발견·탐색 결과 화면은 앱에서 제거한다.

**먼저 문 개방·위치를 충분히 기록할 수 있는지 확인하고, 가능할 때 기억 입력과 방문 복기 화면을 만든다.** 기록이 불가능한 상황을 화면 완성도로 가리지 않는다.

초기 제품은 기록 상태 확인, 방문 이력 복기, 기억 조건 입력, 확인 결과 관리, 기록 삭제까지로 좁힌다. 계정·서버·클라우드 동기화·AI 추론·지도 서비스·음성·내비 직접 연동은 초기 필수 구성으로 두지 않는다. 장소명 자동 변환 없이도 시각·좌표·사용자 이름으로 검증할 수 있게 한다.

## 현재 출발점

### 차량 앱 시각 체계 전면 교체

- 최신 사용자 요청은 기존 디자인 전체 교체이며 선호는 ‘완성도 높은 차량 앱 같은 고급스러움’이다. 앞의 녹색·사이드바·개별 카드 조합을 현재 시각 기준으로 유지하지 않는다.
- 상단 브랜드와 세 메뉴, 한 장의 기록 면, 시각/날짜 고정 열과 장소 열, 오른쪽 동작으로 구성한다. 넓은 Pleos에서는 방문 내용과 버튼을 한 행에 정렬하고 좁은 폭·큰 글자에서는 세로로 전환한다. 개별 방문의 둥근 배경 상자는 제거한다.
- 흰색·먹색·파랑을 기본으로 하고 야간은 짙은 중성 바탕과 밝은 파랑을 사용한다. 선택된 메뉴는 반전된 전체 배경으로 표시하며 한쪽 강조선은 쓰지 않는다. 버튼·입력·기록 면의 모서리는 8dp로 통일한다. 본문 22sp·버튼 24sp/80dp와 시스템 글자 크기·주야간 연동을 유지한다.
- 기능·실제 자료·보관 및 경량 저장 정책은 유지한다. 존재하지 않는 지도·사진·차량 수치를 추가하지 않는다. root `PRODUCT.md`, `DESIGN.md`는 설치된 디자인 도구의 문맥 어댑터이며 제품 정책과 현재 구현 설명의 원본은 이 문서와 출품 주제 문서에 둔다.
- Impeccable의 시각 교체·Operate·Android 기준과 Taste의 앱 화면 원칙을 적용한다. 의존성·스킬·실행기를 새로 설치하지 않으며 브라우저용 스케치나 웹 검사 결과를 실제 Android 구현으로 취급하지 않는다.

### 차량 발자취 명칭·화면 정돈

- 앱 표시 이름·화면 브랜드·기록 알림을 ‘차량 발자취’로 맞추고 방문 지점을 잇는 벡터 아이콘을 사용한다. 애플리케이션 ID·저장 DB는 유지하여 이름 변경으로 기존 자료가 분리되지 않게 한다.
- 사용자가 전역에 제공한 Impeccable의 기존 화면 다듬기·Operate·Android·craft-floor와 Taste의 앱 화면 원칙을 적용했다. 스킬·의존성·실행기를 추가 설치하거나 업데이트하지 않았다. 로컬 Impeccable 컨텍스트 실행기를 사용했으며 네이티브 화면을 웹 DOM 검사 통과로 표시하지 않는다.
- 기존 밝은 바탕·녹색 계열과 큰 글자·80dp 버튼을 유지한다. 날짜는 오늘·어제·날짜 선택을 한 줄에 모으고 좁은 폭에서는 세로로 배치한다. 시간·날짜 열과 장소·정차 시간 열을 정렬하며 반복 방문 동작은 윤곽 버튼으로 낮춘다. 선택 항목은 전체 배경으로 표시하고 한쪽 테두리를 강조하지 않는다.
- 홈의 장식성 상단 날짜를 제거하고 설정을 화면/저장과 보관/연습과 연결 확인/삭제로 묶는다. 기존 수집·경량 저장·방문 복기·메모·정차 제한 정책은 변경하지 않는다. 시스템 글자 크기·다크/라이트와 기본 제어의 누름 피드백을 유지한다.

### 경량 저장·큰 글자 UI 추가

- DB 버전 5는 기존 자료를 유지하며 이벤트의 마지막 수신 시각·관측 횟수와 누적 수신/저장 행 집계를 추가한다. 기존 반복 기록을 소급 삭제하거나 DB 파일 자체를 압축하지 않는다.
- `HistoryStore.event`: 같은 세션·정차·문 영역·값·종류·설명인 조회/반복/상태 알림을 최초 관측에서 60초 이내로 묶는다. 중간에 상태 변화·기준값·불명 값 또는 다른 값/정차가 있으면 합치지 않는다. 실제 전이 건수와 최초/마지막 수신, 횟수를 구분한다.
- `LocationStoragePolicy`: 정지 위치는 정확도를 고려한 이동 오차 범위에서 60초마다 대표점, 이동은 15초 또는 5초 이상 후 50m 변화에서 저장한다. 세션·정차·공급자·정확도 유효성 변경과 단조 시각 후퇴 시 새 기준을 남긴다. 잘못된 좌표는 저장하지 않는다. 수집 상태·정차 위치 요약과 경로 누락 판단은 저장 선별 전 실제 수신값으로 유지한다.
- 설정의 저장 절약 현황은 이번 방식 적용 이후의 누적 수신 건수/저장 행 수이며 파일 압축률이 아니다. 보관 기간·전체 삭제는 기존 정책을 따른다.
- 기본 본문을 최소 22sp, 버튼 24sp·최소 80dp로 키우고 시스템 글자 크기에 맞춰 높이를 늘린다. 버튼은 줄바꿈 시 높이를 확장하며 큰 글자·좁은 화면에서는 방문 동작을 세로로 배치한다. 오늘·어제 빠른 선택을 추가하고 대화상자 메시지·선택 항목·확인 버튼도 크게 표시한다.
- 제출용 제품 설명은 출품 주제 문서의 ‘경량 저장과 쉬운 사용’을 따른다. 합성 저장량 비교와 UI 치수 검증은 실제 고령 사용자 평가·실차 경로 정확도 검증을 대체하지 않는다.

| 위치 | 현재 상태 | 계획에서의 역할 |
| --- | --- | --- |
| `app/` | 기록 서비스·로컬 저장·기억 입력·복기·확인 결과·삭제·시연 모드 구현 | 제품 앱. 실제 검증 결과는 아래 구현 상태에 구분 |
| `tools/vehicle-runtime-probe/` | Vehicle 2.3.2 기반 별도 진단 앱. 이전 조향각·AAOS 속도·기어 읽기 확인 | 문·위치 접근과 수집 수명주기 확인에 필요한 범위로 확장 |
| 개발 환경 | Gradle Wrapper와 Pleos 환경 안내 존재 | 버전은 개발 환경 문서를 따르고 불필요하게 변경하지 않음 |

기존 진단 결과는 문 이벤트·위치·지속 수집의 성공 근거가 아니다. 라이브러리 추가와 호출 구현 전 해당 버전의 공식 계약·권한·제공 상태를 확인한다.

| 0. 시험 준비 | 대상 AVD·SDK 버전·지원 영역·권한 목록 확인. 위치 경로와 정차 판단 신호 선정. 시험 이벤트 순서·허용 누락·지연 기준을 실행 전에 정의 | 시험 환경, 입력과 관측 방법, 합격 기준을 기록. 모의·실제 입력 구분 | 접근 가능한 문·위치 경로가 있어야 실제 수집 단계 진행 |

| 2. 지속 기록 | 로컬 저장과 수집 세션 구현. 다른 앱 전환, 연결 단절·복구, 프로세스 종료·재시작에 따른 기록 확인. 허용된 서비스 실행 방식 검토 | TEST-LOST-001의 기준에 따라 저장 유지·복구·누락 표시 확인 | 반복 수동 실행 없이 핵심 이용 구간을 기록할 수 있어야 제품 구현 진행. 차량 전원 변화는 실차 검증 항목으로 별도 유지 |
| 3. 방문 이력 구성 | 정차 신호와 위치로 방문 구간을 만들고 문 이벤트를 연결. 원시 기록을 보존해 묶음 결과를 재검토할 수 있게 함 | 인접 장소·짧은 정지·위치 끊김을 시험하고 확정 불가 상태를 표시 | 위치 근거 없이 상점명·실내 위치·이동 경로를 확정하지 않음 |

## 코드 책임과 데이터 구성안

아래는 책임 분리를 위한 초안이며 지금 디렉터리나 프레임워크를 일괄 생성하지 않는다. 진단 앱의 실험 코드를 제품에 통째로 복사하지 않고 필요한 수집 처리만 옮긴다.

| 책임 | 처리 범위 |
| --- | --- |
| 차량·위치 수집 | SDK 연결·권한·지원 확인, 영역별 구독, 위치 품질, 연결 상태, 구독 해제 |

| 복기 처리 | 기억 시점·장소·확실성·관련 문 조건 대조, 확인 결과 반영, 기억 변경 후 목록 갱신 |

저장 항목은 세션 ID, 출처(실제/모의), 문 영역·원시 값, 앱 수신 시각, 제공되는 경우의 원본 시각, 위치·정확도·측정 시각, 오류·연결 상태를 기준으로 설계한다. 벽시계 변경과 재부팅을 고려해 세션 및 단조 시각을 함께 검토하며 서로 다른 시계를 그대로 비교하지 않는다.

초기 문 상태 조회는 과거 개방 이벤트로 저장하지 않는다. 반복된 같은 값과 실제 상태 전이를 구분한다. 콜백이 없다는 이유만으로 연결이 정상이라고 판단하지 않으며, 연결 확인·구독 상태·수집 신뢰 범위를 별도로 관리한다. 관측할 수 없었던 구간의 정확한 누락 개수나 시작 시각을 만들어내지 않는다.

현재 구현은 Android 기본 View·SQLite를 사용한다. 정차 판정은 AAOS 속도 절댓값 0.1m/s 미만과 기어 P(4)를 함께 확인하고 2초마다 다시 조회한다. 6초 넘게 갱신되지 않으면 불명으로 돌린다. 위치는 표준 Android `LocationManager` 공급자를 사용하고 측정 후 60초 이내·정확도 100m 이하만 방문의 위치 표시로 연결한다. 이 기준은 초기 구현값이며 실제 장소 정확도·안전성을 입증한 수치가 아니다. 실내 상점명을 자동 지정하지 않는다.

## 검증과 결과 기록

우선 검증 목표와 TEST-LOST-001~003의 판단 원칙은 주제 선정 문서를 따른다. 실행 전 시험별 입력 순서·환경·측정 항목·합격 기준을 구체화하고, 실행 후 원시 로그·관측값·통과 여부·남은 제약을 테스트 단계 문서에 기록한다. 아직 없는 시험 문서를 작성 완료로 링크하지 않는다.

빌드·설치·에뮬레이터 입력·사용자 비교는 실제 수행한 범위만 보고한다. 사용자 구현·검증 요청으로 제품 앱과 진단 앱의 빌드 및 기기 시험을 진행했다. 사람 대상 비교 실험이나 실차 검증을 대신한 것으로 표시하지 않는다.

### 문 이벤트 진단 구현 상태

2026-10-29 `tools/vehicle-runtime-probe`에 읽기 전용 `DoorProbe.kt`를 추가했다. 영역별 capability의 읽기 접근과 범위를 확인하고 초기값 조회·변경 알림 구독·종료 시 해제를 수행하도록 작성했다. `CAR_DOORS` 읽기 권한을 선언하고 기존 진단 관측창을 20초에서 120초로 늘렸다.

- 초기 조회는 `snapshot`, 첫 유효 콜백은 `baseline`, 같은 값은 `repeat`, 값 변경은 `transition`, null·범위 밖 값은 `unavailable`로 기록한다. 위치·물건 이동·문 개방 여부를 원시 값만으로 확정하지 않는다.
- 콜백은 영역·원시 값·수신 단조 시각·수신 벽시계를 logcat으로 출력한다. 원본 이벤트 시각은 미제공으로 표시한다. 오류·알 수 없는 값 뒤에는 기준값을 초기화하며, 알림 부재만으로 연속성을 보장하지 않는다.
- 구독 등록 반환과 실제 콜백 수신을 구분하며, 등록 때와 같은 영역·리스너로 해제를 시도한다.
- 구현 근거는 [Vehicle 2.3.2 공식 배포 소스](https://nexus-playground.pleos.ai/repository/maven-releases/ai/pleos/playground/Vehicle/2.3.2/Vehicle-2.3.2-sources.jar)와 [공식 샘플 안내](https://document.pleos.ai/en/docs/pleos-only/tutorial/vehicle-sdk-sample-app)다. Context7 도구는 제공되지 않아 사용하지 못했다.
- 진단 앱 `assembleDebug`는 성공했다. 제품의 문·위치 수집과 저장은 별도 `app/`에서 구현했다. 전체 수명주기·전원 변화 검증이 끝난 것은 아니므로 TEST-LOST-001 전체 통과로 표시하지 않는다.

### 제품 앱 구현 상태

- `VehicleSignals.kt`: Vehicle 2.3.2 도어 영역별 읽기·구독·재확인, 오류 시 구독 정리·기준값 초기화, AAOS 속도·기어 조회. 초기 조회·첫 알림·반복·상태 전이를 구분한다.
- `RecordingService.kt`: 사용자 동의와 위치 권한 후 시작하는 위치 foreground service. 문·위치·정차를 기록하고 중지 시 구독·위치·차량 연결을 정리한다. 자동 부팅·강제 종료 후 자동 재시작은 하지 않는다.
- `HistoryStore.kt`: 원시 문 이벤트·위치 원본 시각/정확도/공급자·정차 구간·탐색·확인 결과를 SQLite에 저장한다. 수집 중단의 정확한 종료 시각을 알 수 없으면 빈 시각과 불명 사유를 남긴다. 기존 1차 DB에서 위치 테이블을 추가하는 버전 2 마이그레이션을 제공한다.
- `MainActivity.kt`: 기록 권한·동의, 기억 시점/확실성/관련 문 입력, 방문별 근거·확인 결과, 기억 수정, 찾음/미발견 종료, 장소 이름, 전체 삭제. 실제·모의 탐색을 분리하고 실제 기록의 상세 조작은 정차 확인 시만 허용한다. 모의 모드도 이동 신호가 있으면 조작을 잠근다.
- 원시·방문 기록은 새 기록 시작 시 7일 이전 자료를 삭제하고 탐색 메모·결과는 전체 삭제까지 보관한다. 조회는 최근 방문 200개·탐색 100개로 제한한다. 서버 전송·외부 지도·음성·AI·계정·자동 내비 제어는 포함하지 않았다. 앱 백업·기기 전송에서도 데이터를 제외한다.
- 기기 검증에서 `CAR_SPEED` 런타임 권한 누락으로 정차 방문이 생기지 않는 문제를 발견해 홈의 권한 요청·거부 안내를 추가했다. 실제 측정과 원시 시각을 확인하는 위치 경로로 표준 Android API를 사용하며 Pleos FusedLocation의 계정 제공 상태가 해결됐다고 주장하지 않는다.

### 방문 복기 보조 기능 추가

- `NavigationLink.kt`: NaviHelper 3.0.5의 목적지 조회·변경·목적지/경유지 도착·안내 취소 알림을 기록한다. 방문 상세에는 같은 세션에서 정차 시작 2분 전부터 종료까지 수신한 내비 정보를 표시한다. 근접 시각 정보이며 하차·매장 방문의 증명이 아니다. 새 정차 구간에서는 목적지를 다시 조회한다.
- `OdometerCollector.kt`, `CoverageTracker.kt`: Vehicle 2.3.2의 누적 주행 거리(km)를 5초 간격으로 조회한다. 정확도 100m 이내 위치가 15초 동안 갱신되지 않고 거리계가 0.1km 이상 증가하면 홈에 경로 미기록 의심 구간을 표시한다. 불명 값·거리계 감소·60초 초과 관측 단절에서는 기준을 초기화한다. 누락 경로를 생성하지 않는다.
- 실제 방문에 유효한 좌표가 있으면 정차 중 ‘다시 길 안내’를 확인한 뒤 현재 위치에서 해당 좌표로 새 경로를 요청한다. 기존 안내가 변경될 수 있음을 확인 창에 알린다. 연결 대기 중 정차 확인이 사라지거나 앱을 벗어나면 요청하지 않는다. 요청 반환을 길 안내 성공으로 표시하지 않으며 내비에서 결과를 확인하게 한다. 모의 기록에는 버튼을 제공하지 않는다.
- DB 버전 3은 내비 정보와 경로 미기록 의심 구간을 추가한다. 기존 방문 자료를 유지하며 전체 삭제·7일 보관 정책을 적용한다. 자동 내비 제어는 계속 제외하고 사용자 확인을 거친 요청만 추가했다.
- 계약 근거: [NaviHelper 3.0.5 공식 배포 소스](https://nexus-playground.pleos.ai/repository/maven-releases/ai/pleos/playground/NaviHelper/3.0.5/NaviHelper-3.0.5-sources.jar), [Vehicle 2.3.2 공식 배포 소스](https://nexus-playground.pleos.ai/repository/maven-releases/ai/pleos/playground/Vehicle/2.3.2/Vehicle-2.3.2-sources.jar). Context7 도구는 제공되지 않아 공식 배포 소스를 확인했다. 실제 도착 이벤트와 내비의 좌표 경로 수락은 별도 기기 검증 대상이다.

### 화면 개편과 화면 모드

- 2026-10-29 사용자 요청에 따라 기존 Android Views 화면을 재구성했다. 홈은 기억 찾기 시작·간단한 수집 상태·방문 타임라인, 탐색은 물건별 상태, 입력은 기억 조건, 설정은 모드·수집 상세·보관·시연·삭제로 구성한다.
- 방문 카드에는 시각·정차 시간·장소·위치 확보 여부와 상세/길 안내 동작만 우선 표시한다. 좌표·정확도·문 원시 정보는 상세로, SDK 수신 상태·보관 설명·시연 모드는 설정으로 옮긴다. 반복된 설명과 홈의 시연 버튼은 제거한다. 데이터 수집·탐색·정차 제한 정책은 유지한다.
- `values`와 `values-night`의 색·플랫폼 테마를 분리한다. 라이트는 아이보리·딥그린, 다크는 차콜·라임을 사용한다. 기본값은 시스템 연동이며 설정에서 이 앱만 라이트·다크로 고정할 수 있다. 차량 전체 화면 모드를 변경하지 않는다.
- 모드 변경으로 Activity가 다시 만들어질 때 현재 페이지·물건 입력 초안·탐색 선택을 저장/복구한다. 입력·선택 상태는 색만으로 표현하지 않으며, 선택된 탐색 항목은 전체 배경색으로 표시한다. 터치 동작은 최소 56dp 높이를 유지한다.
- [Android 공식 다크 테마 안내](https://developer.android.com/develop/ui/views/theming/darktheme)의 night 리소스·시스템 구성 변경 계약을 사용했다. Context7은 제공되지 않아 공식 문서로 확인했다. 검증 범위와 결과는 관련 앱 검증 문서에서 관리한다.

### UX 흐름 정리

- 홈의 소개 문구·큰 장식 영역을 제거하고 방문 목록을 먼저 확인하게 한다. 진행 중인 최신 탐색은 홈에서 바로 이어가며, 최근 5곳 외 저장된 방문도 펼쳐 볼 수 있다. 탐색 목록은 진행 중/종료됨을 구분한다.
- 기억 입력은 물건 이름만 필수다. 시점·확실성·메모·관련 문은 선택 영역으로 접고, 접어도 입력을 보존한다. 시점이 없으면 확실성 체크를 표시하지 않는다. 빈 이름 오류는 해당 입력란에 표시하며 제출 시 키보드를 닫는다.
- 입력 중 메뉴·취소·뒤로가기로 이탈할 때 변경이 있으면 나가기/계속 입력을 선택한다. 복기에서 뒤로가면 탐색 목록으로 돌아간다. 같은 화면에서 기록이나 확인 상태를 갱신할 때 스크롤 위치를 유지한다.
- 방문 목록에서 확인 결과를 직접 남긴다. 상세→확인 결과의 두 단계 이동은 필수가 아니며, 기존 상세에서도 접근할 수 있다. 상세 창의 중복 닫기 동작은 제거하고 수집 진단은 설정에서 요청할 때 표시한다. 좁은 화면의 방문 버튼은 세로 배치한다.
- 다크·라이트 선택, 정차 제한, 실제/모의 분리, 저장·삭제 정책은 유지한다. 구현 위치는 `MainActivity.kt`이며 UX 검증 결과는 관련 앱 검증 문서를 따른다.

## 미정 사항과 다음 작업

- **남은 확인:** 실차의 문 상태 변화·차량 전원 변화·장시간 연결 단절과 복구, 사용자 비교 실험, 배포 서명·마켓 심사. 코드 구현 완료와 이 항목의 검증 완료를 구분한다.
- 위치 SDK 제공 상태·대체 API의 권한·대상 환경 지원, 백그라운드·자동 재시작 허용 범위 확인 필요.
- 전원 종료 전후의 누락은 핵심 위험이다. 에뮬레이터에서 확인한 항목과 실차에서만 확인할 항목을 나눠 기록한다.
- 로컬 저장은 앱 기본 보안 영역을 사용하고 별도 DB 암호화·앱 로그인은 구현하지 않았다. 공용 차량에서는 같은 OS 사용자 내 기록을 공유할 수 있으므로 앱에서 안내한다. 외부 전송은 범위에 포함하지 않는다.
- 사용자 비교 표본·수치 기준·사업성, 장기 운영 기준·일정·출품 서명은 미정이다. 현재 화면과 저장 기술은 위 구현 상태를 따른다.
