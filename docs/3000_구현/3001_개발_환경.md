# 개발 환경

## 문서 정보

- 상태: 초안.
- 적용 범위: Kotlin Android 앱 골격과 로컬 개발 환경. 제품 기능·SDK 연동은 제외한다.
- 근거: 2026-10-28 사용자가 Kotlin·Android Studio·Pleos 에뮬레이터 환경 구성을 승인했다.
- 관련 요구사항: REQ-CONTEST-009. 제품별 SDK 선택과 권한은 미정이다.

## 목적과 범위

Android Studio에서 저장소를 열어 개발할 기본 앱을 준비한다. 서비스 기획·아키텍처·개발 방법론은 미정이며, 이번 환경 구성으로 확정하지 않는다.

## 프로젝트 설정과 실행 방법

| 항목 | 설정 |
| --- | --- |
| 앱 모듈 | `app/` |
| Kotlin | 2.2.10 |
| Android Gradle Plugin | 8.9.2 |
| Gradle | 8.13 |
| Android SDK | minSdk 28 / compileSdk 35 / targetSdk 34 |
| Java·Kotlin 바이트코드 | JVM 17 |
| 임시 애플리케이션 ID | `dev.onboard.app` — 배포 전 소유 도메인·식별자 결정 필요 |

Android Studio에서 저장소 루트를 연다. SDK 위치는 IDE가 생성하는 `local.properties` 또는 `ANDROID_HOME`으로 지정하며 로컬 경로는 커밋하지 않는다. Gradle 실행 JDK는 17 이상을 사용하고 Java·Kotlin 출력은 17로 맞춘다. 앱은 Android 기본 Activity와 이름 표시만 제공하며 별도 UI 라이브러리는 채택하지 않았다.

`compileSdk`는 컴파일 기준이고, Pleos 에뮬레이터 API 34와 별개다. targetSdk 34는 초기 전용 실행 환경에 맞춘 값이며 마켓 제출 정책 충족을 확정하지 않는다.

## 로컬 환경과 남은 설치

2026-10-28 파일 조회에서 Android Studio 2025.3.3, Microsoft JDK 21, Android SDK Platform 34·35와 Build Tools 35.0.0을 확인했다. 기존 AVD는 Pixel 계열이며 Pleos 전용 AVD는 확인되지 않았다. 설치 파일의 존재는 앱 실행 성공을 의미하지 않는다.

이후 사용자가 제공한 화면에서 Android Studio의 가상 기기 생성 화면과 Pleos 전용 이미지 목록을 확인했다. 가상 기기 생성 완료·부팅·앱 실행은 아직 확인하지 않았다.

## Pleos 에뮬레이터 설정 방법

Windows 기준이다. 에뮬레이터 설치·생성에는 앱 프로젝트를 열거나 새 프로젝트를 만들 필요가 없다. 아래 절차는 공식 설치 가이드와 2026-10-28 사용자가 제공한 Android Studio 화면을 기준으로 한다. 버전에 따라 탭 이름이 다를 수 있다.

### 1. SDK Manager 열기

- 시작 화면: `More Actions > SDK Manager`.
- 프로젝트를 연 상태: `Tools > SDK Manager`.
- `Android SDK Location`은 기존 SDK 경로를 유지한다.

### 2. Pleos 다운로드 주소 등록

1. `SDK Update Sites` 탭을 연다.
2. `+`를 눌러 다음 항목을 등록한다.

| 항목 | 입력값 |
| --- | --- |
| Name | `Pleos Connect System Image` |
| URL (Windows/Linux) | `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-sys-img.xml` |

3. 등록 창에서 `OK`를 누른다.

### 3. Pleos 시스템 이미지 설치

1. `SDK Platforms` 탭으로 이동한다.
2. 오른쪽 아래 `Show Package Details`를 체크한다.
3. `Android 14.0 (UpsideDownCake)`의 기본 `API 34` 항목을 찾는다. `34-ext` 항목과 구분한다.
4. 하위 목록에서 Pleos Connect 시스템 이미지를 체크한다. Android 14 상위 행의 체크만으로 Pleos 이미지 선택을 판단하지 않는다.
5. `Apply > OK`로 설치를 진행하고 완료 후 `Finish`를 누른다. 라이선스 동의가 나타나면 내용을 확인하고 진행한다.
6. Android Studio를 재시작한다.

### 4. 가상 차량 생성

1. 시작 화면에서는 `More Actions > Virtual Device Manager`, 프로젝트에서는 `Tools > Device Manager`를 연다.
2. `+` 또는 `Create Device`를 누른다.
3. 기기 분류 `Automotive`에서 `Pleos Connect v2.1.0`을 선택하고 `Next`를 누른다.
4. `Configure virtual device` 화면의 `Device` 탭에서 API를 `API 34 / Android 14.0`으로 선택한다.
5. 이미지 목록의 **`Pleos Connect v2.1.0 APIs Intel x86_64 Atom System Image`** 행을 클릭한다. 사용자 화면에 함께 표시된 일반 `Android Automotive with Google APIs` 이미지와 구분한다.
6. `Additional settings` 탭에서 아래 값을 설정한다. 공식 가이드의 다른 UI에서는 `Advanced Settings`라는 이름을 사용한다.

| 항목 | 설정값 |
| --- | --- |
| RAM / RAM Size | `4 GB` 또는 `4096 MB` |
| Startup > Default boot | `Cold` |

7. `Finish`로 가상 기기를 생성한다.

### 5. 실행 및 완료 확인

Device Manager에서 생성한 Pleos 기기 옆 `▶`를 누르고 부팅을 기다린다. Pleos 차량 화면이 표시되면 에뮬레이터 부팅까지 확인된 상태다. 앱 설치·실행과 SDK 연결은 별도 확인이 필요하다.

Pleos Playground 계정·프로젝트 및 SDK 제공 상태는 사용자 계정에서 확인한다. 자격 증명은 저장소에 기록하지 않는다.

### 6. 가상 차량 입력 콘솔

[공식 설치 안내](https://document.pleos.ai/en/docs/connect/guide/getting-started/application-development/use-vehicle-emulator)에 따르면 Virtual Console은 에뮬레이터 2.1.0 이상에서 사용할 수 있다. Pleos 기기를 부팅한 뒤 다음 명령을 실행하고 PC 브라우저에서 `http://127.0.0.1:8088/`을 연다. 기기가 여러 대면 `-s`로 대상 에뮬레이터를 지정한다.

```powershell
adb -s emulator-5554 forward tcp:8088 tcp:8088
```

`Emulation Controls > Motion`에서 기어·브레이크·조향 등 가상 입력을 바꿀 수 있다. [공식 사용 가이드](https://document.pleos.ai/en/docs/pleos-only/app-test-guide/virtual-console-guide)는 Steering Angle을 운전대 각도 -540~540도로 설명한다. SDK가 설명하는 앞바퀴 각도와 같은 값이라고 가정하지 않는다. 설정 후 시험 앱에서 get·callback을 별도로 확인한다. 에뮬레이터의 일반 `Extended Controls > Virtual sensors`와 Pleos Virtual Console은 구분한다.

현재 확인 범위는 ADB 포워딩 명령 성공과 공식 사용법 조사다. 콘솔 웹 화면의 연결·가상 입력 변경 시험은 아직 수행하지 않았다. 시험 종료 후 필요 없어진 포워딩은 다음 명령으로 제거한다.

```powershell
adb -s emulator-5554 forward --remove tcp:8088
```

### 문제 발생 시

- **Pleos 이미지가 보이지 않음:** `SDK Update Sites` 주소와 활성화 상태, `Show Package Details`, 기본 API 34 항목을 확인한다.
- **Finish가 비활성화됨:** Pleos 시스템 이미지 행을 실제로 선택했는지 확인한다. 이미지를 아직 설치하지 않았다면 다운로드·설치를 마친다.
- **Start Failed / DirectoryLock 오류:** 오류가 지목한 기존 `studio64.exe` 프로세스가 남았을 수 있다. 시작·종료 중이면 기다린다. 계속 응답하지 않으면 저장하지 않은 작업의 손실 가능성을 확인한 뒤 작업 관리자에서 해당 PID를 종료하고 다시 실행한다. PID는 실행마다 달라지므로 이전 번호를 재사용하지 않는다. 이 오류만으로 `Reset Settings & Plugins`를 실행하지 않는다.

## 구현 순서와 검증 상태

`gradle wrapper --gradle-version 8.13 --distribution-type bin`으로 Wrapper 생성이 완료됐다. 이 작업은 앱 컴파일·실행 검증이 아니다.

제품 앱에는 Vehicle 2.3.2, 도어 읽기·AAOS 속도/기어·표준 Android 위치 권한을 추가했다. 속도·위치의 런타임 권한은 앱에서 요청한다. 위치는 Android `LocationManager`를 사용하며 음성·NaviHelper·Pleos FusedLocation SDK는 추가하지 않았다.

2026-10-29 사용자 요청으로 `app`의 debug/release 빌드·단위 테스트·린트와 기존 Pleos AVD의 기기 시험을 수행했다. 상세 범위는 [구현 계획](3002_분실물_역추적_구현_계획.md)의 앱 검증 문서를 따른다. 별도 진단 앱의 기존 실행은 [SDK 검증 결과](../4000_테스트/4001_SDK_검증_결과.md)에 구분한다. release 산출물은 미서명이며 배포 키와 제출용 서명은 미완료다.

## 미정 사항과 확인 필요 사항

- Pleos 에뮬레이터에서 제품의 기본 흐름·문/위치 저장·앱 전환 후 기록을 확인했다. 실차와 차량 전원 변화·실제 문 전이 입력은 별도 검증이 필요하다.
- 제품 기능, SDK 버전·권한, 배포용 applicationId와 서명 정책.
- 개발 방법론, 비기능 목표와 사용자가 선택할 검증 범위.
