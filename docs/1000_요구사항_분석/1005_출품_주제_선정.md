# 출품 주제 선정

## 문서 정보

- 상태: 확정. 주제 유지와 검증 우선순위에 대한 결정이며, 제품 기능·기술·차별성의 검증 완료를 뜻하지 않는다.
- 근거: 2026-10-28 주제 선정 및 2026-10-29 사용자 지시로 재검토 결과와 진행 조건을 반영한다.
- 적용 범위: 기획 방향, 차별성 가설, 개발에 앞서 확인할 조건. 상세 설계·전체 기능 요구사항은 미정이다.
- 관련 요구사항: REQ-CONTEST-001, REQ-CONTEST-006, REQ-CONTEST-009.

## 목적과 범위

**2026-10-29 최신 결정: 실제 앱은 차량 방문·이동 이력 복기를 중심으로 제공한다. 물건 찾기는 기획의 활용 사례로만 남기고 앱 메뉴·입력·결과 처리에서 제외한다.** 이전 DEC-LOST-001의 제품 화면 방향은 이 결정으로 대체한다. 아래 분실물 설명과 가설은 기획 검토 이력이며 현재 앱 기능의 설명이 아니다.

- 앱의 기본 흐름은 날짜별 방문 보기 → 특정 방문부터 시간순 복기 → 상세·실측 이동 위치 확인 → 방문별 메모다. 물건 이름·분실 확률·찾음/미발견 상태는 제공하지 않는다.
- 내비 알림은 방문 증명이 아니고, 좌표 목록은 실제 도로 경로의 복원이 아니다. 기록 시작 전·수집 누락 구간은 복원하지 않는다.
- 기획 활용 사례: 나중에 물건을 찾으려는 사람이 과거 방문을 돌아보는 데 도움을 줄 수 있다. 자동 탐지나 분실 장소 판정을 구현한 것으로 설명하지 않으며 효과·차별성은 별도 검증 대상이다.

## 제출 기획 반영 · 경량 저장과 쉬운 사용

**제출용 설명:** 차량 발자취는 차량 방문 이력을 기기 안에 가볍게 남겨 누구나 쉽게 돌아보는 앱이다. 같은 차량 상태는 매번 별도 행으로 쌓지 않고 관측 횟수와 처음·마지막 수신 시각으로 묶는다. 위치는 정차와 이동의 변화에 맞춰 선별 저장한다. 큰 글자와 넓은 버튼, 오늘·어제 바로 보기로 기록을 쉽게 확인하도록 설계했다.

- 구현: 같은 조회·반복 상태를 최대 60초 구간으로 묶고, 실제 상태 변화·초기 기준·알 수 없는 상태는 따로 남긴다. 위치는 새 정차·수집 세션·공급자·정확도 유효성 변화에서 보존하고, 그 밖에는 정지 시 최대 60초 간격, 이동 시 15초 또는 5초 이상 경과 후 50m 변화 기준으로 선별한다.
- ‘경량’은 파일 전체의 무손실 압축이 아니라 중복 행 축약·위치 표본 선별이다. 중간 위치와 반복 수신의 개별 시각은 일부 생략되며 경로 정밀도를 보장하지 않는다. 문 상태 변경은 보존하고 수집 누락 판단은 선별 전 실제 수신값을 사용한다.
- UI 기본값: 본문 최소 22sp, 버튼 24sp·최소 80dp 높이, 시스템 글자 크기 반영, 큰 확인 버튼, 오늘/어제 바로 선택, 차량 진단 정보는 별도 화면에 둔다. 다크·라이트와 정차 제한을 유지한다. 수치는 제품의 자체 설계 기준이며 공식 접근성 인증을 뜻하지 않는다.
- 검증과 표현 한계: 동일 입력의 일반 저장/경량 저장 비교와 기기 글자·버튼 치수를 시험한다. 절감률을 제출할 때는 입력 조건·행 수·SQLite 할당 크기를 함께 적고 실차 평균 절감률이나 고령 사용자 사용성 검증으로 확대하지 않는다. 실제 대상 사용자 과제 수행 시험은 별도로 필요하다.
- 제출에 사용할 수 있는 측정 예시: 5초마다 같은 정차 위치·차량 조회를 각각 1,200건 넣은 약 100분 합성 입력에서 위치 행은 1,200→100, 차량 행은 1,200→93, SQLite 페이지 할당량은 216KiB→84KiB로 약 61.1% 감소했다. 동일 스키마의 빈 시험 DB 비교이며 실제 주행·기존 자료·저널 파일은 포함하지 않았다. 이 수치는 해당 정차 조건의 결과로만 제시한다.
- 접근성 참고: [Android 공식 Views 접근성 지침](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views). Context7 도구는 제공되지 않아 공식 문서로 확인했다. 구현 세부와 실제 측정 결과는 관련 구현·검증 문서에서 관리한다.

## 분실물 활용 시나리오 · 기획 검토 이력

차로 여러 곳을 다녀온 뒤 물건이 없어진 경우, 마지막으로 본 기억과 차량의 문 개방·정차 이력을 대조해 어디부터 다시 확인할지 정하는 Pleos Connect 앱을 검토한다. 내연기관·하이브리드·전기차의 공통 상황을 대상으로 한다.

물건의 위치나 이동을 직접 감지하는 기능, 태그·별도 센서·카메라 영상·외부 기관 제휴가 필수인 구성은 초기 범위에서 제외한다. 차량에 접근할 수 없는 차키 분실 등도 초기 대상에서 제외한다.

## 결정과 핵심 가설

**DEC-LOST-001: 출품 주제는 ‘태그 없는 분실물의 역추적’으로 유지한다. 첫 개발 과제는 자동 기록 가능성 확인으로 정한다.**

문 개방과 위치를 실제로 기록할 수 있는지 확인하고, 단순 방문지 목록보다 도움이 되는지를 비교한 뒤 상세 제품 기획을 구체화한다. 사용자가 매번 물건을 등록하거나 정차 때마다 앱을 조작해야 한다면 초기 기획의 가치를 재검토한다.

차별성 가설은 **물건을 사전에 등록하지 않아도, 분실한 뒤 기억과 차량 접근 기록을 함께 복기할 수 있다는 것**이다. 같은 기능이 없다는 사실이나 효과가 입증된 것은 아니다. 태그 없음·큰 화면·AI 적용만으로 독창성을 주장하지 않는다.

## 사용 흐름과 판단 원칙

1. 기록 기능이 동작한 구간에서 문 개방·정차·위치와 수집 상태를 남긴다. 기록 시작 전의 과거 이력을 복원한다고 가정하지 않는다.
2. 사용자가 정차 중 앱을 열고 찾는 물건, 마지막으로 본 시점·장소와 기억의 확실성을 입력한다. 관련 문은 선택 입력으로 검토한다.
3. 해당 구간의 방문지와 관련 문 개방 기록을 함께 보여준다. 예를 들어 ‘마트에서 지갑을 봤다’는 기억 이후의 정차지를 복기한다.
4. 사용자가 확인할 곳을 선택하고, 확인 결과를 남기거나 ‘찾음 / 탐색 종료’로 마친다.

- 문 열림은 물건 이동이나 승하차한 사람의 신원을 증명하지 않는다. 문이 열리지 않았다는 이유로 특정 장소를 후보에서 제거하지 않는다.
- 수집 누락, 위치 불명, 차내 잔류 가능성, 기억 오류를 함께 표시한다. 기록이 없을 때는 ‘문이 열리지 않음’ 대신 ‘기록 없음’을 구분한다.
- 분실 위치를 확정하거나 근거 없는 확률·자동 우선순위를 제시하지 않는다. 확인 순서는 사용자 선택을 기본으로 검토한다.
- 권한 거부·미지원·연결 끊김은 데이터 없음과 구분한다. 위치·차량 이력의 보관 기간, 삭제, 공유 범위는 구현 전에 정한다.

## 현재 상태와 미정 사항

- 주제 유지와 자동 기록 우선 검증 방향은 확정했다. 세계 최초·신규성·사용자 효과·실차 지원은 미검증이다.
- 2026-10-29 `adb devices -l` 조회 당시 연결된 기기가 없어 이번 재검토에서는 실행 시험을 수행하지 못했다. 이전 조향각·속도·기어 읽기는 이 주제의 문 이벤트·위치·지속 수집을 검증한 결과가 아니다.
- 상세 요구사항·화면·저장 구조·권한과 위치 API 선택, 보관·삭제 정책은 미정이다. 사업성·사용자 수요·지속 이용 의향도 확인이 필요하다.
- 시험의 수치 기준·사용자 표본·실차 환경·개발 방법론은 미정이다. 측정 전에 확정하고, 결과에 맞춰 사후 기준을 만들지 않는다.
